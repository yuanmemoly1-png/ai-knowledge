# 小白课：Agent 记忆（慢速版）

上一课：[[小白课-ReAct思考行动循环]]

> [!note] 这节课学什么
> 前三课的 Agent 有个隐藏设定你可能没注意：**模型自己什么都记不住**。它每回完一张纸条，就把之前的事忘得一干二净——它之所以"记得你叫小明"，全靠程序每次把旧纸条一起塞进去。
> 这节课解决一个问题：纸条越攒越多、塞不下了怎么办？学三招：全量重发、滑动窗口、摘要压缩，最后给一张取舍表。

---

## 第 1 步：先接受真相——记性为零，全靠塞纸条

LLM 没有记忆。每次调用都是一次全新的"读纸条→回纸条"。聊天机器人看起来记得你，真相是：**你的每一次提问，程序都偷偷把整段聊天记录附在后面一起发了过去。**

```text
你以为：              实际上程序发的：
「我叫小明」          纸条1：我叫小明
「我叫什么？」  →     纸条2：我叫什么？
                      ↑ 两张一起塞，模型才答得出
```

这一堆一起塞进去的纸条，总量就叫**上下文（Context）**。详拆见 [[小白课-幻觉与上下文窗口]]。

## 第 2 步：真跑——全量重发，纸条越攒越多

```python
history = []
turns = ["我叫小明", "我喜欢吃辣", "我住在北京", "我叫什么名字？"]
for t in turns:
    history.append({"role": "user", "content": t})
    print(f"第{len(history)}轮，塞给模型的纸条共 {len(history)} 张")
```

真实输出：

```text
第1轮，塞给模型的纸条共 1 张
第2轮，塞给模型的纸条共 2 张
第3轮，塞给模型的纸条共 3 张
第4轮，塞给模型的纸条共 4 张
```

看趋势：**每多聊一轮，塞进去的纸条就多一张**（真实场景还要算上模型自己的回复和工具结果，长得更快）。这带来两个麻烦：

- **塞不下**：上下文窗口有上限，超了直接报错。
- **烧钱**：每张纸条都是 Token，全量重发意味着旧内容**每一轮都重复付费**。聊 50 轮，第 1 句话被付钱了 50 次。见 [[小白课-Token与计费]]。

> [!warning] 上下文超长的典型报错
> 纸条塞爆窗口时，API 会报类似 `context_length_exceeded` 的错。新手常以为"模型坏了"，其实是 history 只增不减。遇到了去查 [[新手报错速查]]。

## 第 3 步：第一招——滑动窗口，只带最近几张

**滑动窗口**：只保留最近 N 张纸条，更早的直接扔掉。Python 里就一行切片：

```python
window = history[-2:]
print(f"滑动窗口（窗口=2）：{len(history)} 张只带 {len(window)} 张")
for m in window:
    print("  带上：", m["content"])
```

真实输出：

```text
滑动窗口（窗口=2）：4 张只带 2 张
  带上： 我住在北京
  带上： 我叫什么名字？
```

`history[-2:]` 就是"倒数第 2 张到最后一张"（[[小白课-Python列表与字典]] 学的负数号码）。

图解：

```text
旧纸条：[1][2][3][4][5][6][7][8]
                 ┌─────────────┐
只带最近4张 →    │ [5][6][7][8] │ 塞给模型
                 └─────────────┘
   窗口跟着新纸条往前滑，旧的自然掉出去
```

代价一目了然：上面的输出里，"我叫小明"被扔掉了——所以模型答不出"我叫什么名字？"。**重要信息一旦滑出窗口，就真忘了。**

## 第 4 步：第二招——摘要压缩，旧纸条缩成一张纸

**摘要（Summary）**：让模型自己把一大堆旧纸条压成一张"会议纪要"，以后只带这张纪要 + 最近的新纸条。

```python
old = ["我叫小明", "我喜欢吃辣", "我住在北京"]
summary = "用户叫小明，爱吃辣，住北京"   # 假装这是模型压出来的
print(f"摘要压缩：{len(old)} 张旧纸条 → 1 张摘要")
print("  摘要：", summary)
```

真实输出：

```text
摘要压缩：3 张旧纸条 → 1 张摘要
  摘要： 用户叫小明，爱吃辣，住北京
```

图解：

```text
旧纸条 [1][2][3][4][5][6]
   │
   │ 模型读一遍，压成一张
   ▼
摘要 [S:"用户叫小明，爱吃辣…"] + 最近的新纸条 [7][8]  →  塞给模型
```

关键信息（"叫小明"）进了纪要，不会再丢。代价：压缩本身要**额外调一次模型**（又是一笔 Token 费），而且摘要可能丢细节——"喜欢吃微辣不要香菜"可能被压成"爱吃辣"。

## 第 5 步：三种策略取舍表

| 策略 | 做法 | 好处 | 代价 | 适合场景 |
| --- | --- | --- | --- | --- |
| 全量重发 | 历史全带上 | 啥也不丢，代码最简单 | 越来越贵，迟早塞爆 | 短对话、调试期 |
| 滑动窗口 | 只带最近 N 张 | 便宜，长度永远可控 | 旧的重要信息会真忘 | 闲聊、 FAQ 机器人 |
| 摘要压缩 | 旧的压成纪要 + 新的全带 | 重要信息留得住，长度可控 | 多一次调用费，摘要丢细节 | 长任务、客服、Agent |

真实产品一般是**组合拳**：最近几轮全量 + 更早的摘要 + 特别重要的事实（如"对花生过敏"）单独抽出来长期存。这套工程做法的细节在 [[记忆与上下文工程]]。

## 最关键的一句

> [!important]
> **模型的"记忆"是假的，全靠程序每次把旧纸条塞回去；塞不下就三选一——全量（贵）、滑窗（会忘）、摘要（折中）。**

## 大白话翻译表

| 术语 | 大白话 |
| --- | --- |
| 上下文 Context | 一次塞给模型的全部纸条 |
| 全量重发 | 每轮把整段历史都带上 |
| 滑动窗口 | 只带最近 N 张，旧的扔掉 |
| 摘要 Summary | 旧纸条压成一张会议纪要 |
| `history[-N:]` | 切片：取最后 N 张纸条 |

1. 模型"记得你叫小明"的真正原因是什么？
2. 全量重发策略聊得久了会踩哪两个坑？
3. `history[-2:]` 取出的是哪几张？
4. 客服机器人要处理聊半天的长对话，三种策略选哪个？为什么？

<summary>点我看答案</summary>

1. 程序每次调用都把包含"我叫小明"的旧纸条一起塞了进去，模型是重新读到的，不是记得的。
2. 一是上下文窗口塞爆报错（context_length_exceeded）；二是旧内容每轮重复计费，越来越贵。
3. 最后两张（倒数第 2 张到倒数第 1 张）。
4. 摘要压缩（或组合方案）——全量会塞爆，滑窗会忘掉用户开头说的问题，摘要能把关键信息留下来且长度可控。
