# 小白课：工具调用（慢速版）

上一课：[[小白课-Agent传纸条循环]]

> [!note] 这节课学什么
> 上一课的暗号 `TOOL:get_weather:北京` 是我们随手定的，真实世界不用这么粗糙的格式。这节课学真实的"工具调用"三件套：
> - **工具说明书（schema）**：上岗前发给 LLM 看的，分三部分
> - **JSON 暗号**：LLM 要工具时写的标准纸条格式
> - **一次完整调用**：模型说要调 → 程序执行 → 结果回传，用字典模拟真跑一遍

---

## 第 1 步：先搞懂 JSON——暗号的标准写法

**JSON** 就是一种"填表格式"：花括号 `{ }`，里面 `名字: 内容`，长得像 Python 字典。它在 AI 世界的地位相当于"官方指定纸条格式"——LLM 写它，程序读它。

Python 里来回转换只要两行：

```python
import json

text = '{"name": "get_weather", "city": "北京"}'   # 一段JSON文字
data = json.loads(text)          # 文字 → 字典
print(type(data))
print(data["city"])

back = json.dumps(data, ensure_ascii=False)  # 字典 → 文字
print(back)
```

真实输出：

```text
<class 'dict'>
北京
{"name": "get_weather", "city": "北京"}
```

记住两个词：`loads`（读进来，文字变字典）、`dumps`（写出去，字典变文字）。

> [!warning] JSON 和字典的细微差别
> JSON 文字里**只能用双引号**，写单引号 `{'name': ...}` 会解析失败报 `json.decoder.JSONDecodeError`。遇到了去查 [[新手报错速查]]。另外 `json.dumps` 不加 `ensure_ascii=False`，中文会变成 `\u5317\u4eac` 这种天书——不是错了，是没解码。

## 第 2 步：工具说明书（schema）三部分慢拆

LLM 上岗前，你会把每个工具的**说明书**发给它，它才知道手下有哪些跑腿、怎么下指令。说明书固定写三样：

```json
{
  "name": "get_weather",
  "description": "查询某个城市的实时天气",
  "parameters": {
    "type": "object",
    "properties": {
      "city": {"type": "string", "description": "城市名，比如 北京"}
    },
    "required": ["city"]
  }
}
```

逐行拆：

- **`name`（名字）**：这活叫什么。LLM 下指令时照这个名字喊。
- **`description`（干什么）**：一句话说用途。**LLM 全靠这句话决定什么时候用它**——写得含糊，它就乱用。
- **`parameters`（参数）**：干活前必须提供的信息。`properties` 列出每个参数的名字和类型，`required` 列出哪些是必填。

> [!warning] description 写得太随便 = 工具白装
> 新手常写 `"description": "天气"`，结果 LLM 在该用的时候不用、不该用的时候乱用。把它当成给新人的岗位说明写：**什么场景用、需要什么信息**，写清楚。这是 [[工具调用实战]] 里排第一的坑。

## 第 3 步：LLM 的"我要调工具"纸条长什么样

模型决定用工具时，输出的是一张标准 JSON 纸条，就两个信息：**调谁、带什么参数**：

```json
{
  "name": "get_weather",
  "arguments": {"city": "北京"}
}
```

你的程序收到后干三件事：按 `name` 找到真函数 → 把 `arguments` 塞进去执行 → 把结果塞回去。下一步真跑。

## 第 4 步：最小完整演示（字典模拟模型，真能跑）

不连真 API，用一个字典假装模型的输出，把"说要调 → 执行 → 回传"完整走一遍：

```python
import json

# 第A步：模型的输出（我们用字典假装）
model_output = {"tool_call": {"name": "get_weather", "arguments": {"city": "北京"}}}
print("模型写的暗号：", json.dumps(model_output["tool_call"], ensure_ascii=False))

# 第B步：程序里准备好的真工具
def get_weather(city):
    return f"{city}：小雨，26度"

tools = {"get_weather": get_weather}    # 工具花名册：名字 → 真函数

# 第C步：程序照暗号干活
call = model_output["tool_call"]
func = tools[call["name"]]              # 按名字找到真函数
result = func(**call["arguments"])      # 把参数塞进去执行
print("程序执行结果：", result)

# 第D步：结果塞回去给模型（下一轮它就能回答了）
print("塞回给模型的纸条：", json.dumps({"tool_result": result}, ensure_ascii=False))
```

真实输出：

```text
模型写的暗号： {"name": "get_weather", "arguments": {"city": "北京"}}
程序执行结果： 北京：小雨，26度
塞回给模型的纸条： {"tool_result": "北京：小雨，26度"}
```

四个新东西，逐个说：

- `tools = {"get_weather": get_weather}`：函数也能装进字典！这本"花名册"让程序能按名字找到函数，不用写一堆 if。
- `call["name"]` 取名字，`call["arguments"]` 取参数——就是 [[小白课-Python列表与字典]] 学的按名字取东西。
- `func(**call["arguments"])`：`**` 是"把字典拆成参数"的意思。`{"city": "北京"}` 拆开就变成 `func(city="北京")`。

## 第 5 步：一步一图解——这次调用在时序里的位置

```text
你                模型(LLM)                你的程序
│                   │                        │
│──"北京天气?"─────►│                        │
│                   │──tool_call───────────►│ ① 模型说要调
│                   │  {name:get_weather,    │
│                   │   args:{city:北京}}    │
│                   │                        │──② 花名册找函数、执行
│                   │◄──tool_result──────────│ ③ 结果回传
│                   │  "北京:小雨,26度"       │
│◄──最终答案────────│                        │ ④ 模型看着结果作答
```

和上一课的传纸条图一模一样——只是暗号从 `TOOL:...` 升级成了标准 JSON。**框架（LangChain、各种 Agent 库）做的事，本质就是这张图的 ①②③④。**

## 最关键的一句

> [!important]
> **工具调用 = 给模型看说明书（schema），模型回 JSON 暗号（调谁+参数），你的程序照暗号执行真函数、把结果塞回去。模型从头到尾没碰过工具一根手指头。**

## 大白话翻译表

| 术语 | 大白话 |
| --- | --- |
| JSON | 官方填表格式，花括号+双引号 |
| `json.loads / dumps` | 文字变字典 / 字典变文字 |
| schema 工具说明书 | 名字+用途+参数，上岗前发给模型 |
| arguments 参数 | 干活前必须提供的信息 |
| tool_call | 模型写的"我要调工具"纸条 |
| 花名册 tools 字典 | 名字 → 真函数的对照表 |

## 检查一下

1. 工具说明书的三个部分分别是什么？哪一部分最影响模型"用不用这个工具"的判断？
2. `json.loads('{"a": 1}')` 得到什么？反过来把字典变回 JSON 文字用什么？
3. `func(**{"city": "北京"})` 等价于哪一行普通调用？
4. 模型的 `tool_call` 纸条里必须有哪两个信息？

<details>
<summary>点我看答案</summary>

1. name、description、parameters；其中 description 最影响模型的使用判断，要写清楚。
2. 得到一个字典 `{'a': 1}`；反过来用 `json.dumps(字典)`。
3. `func(city="北京")`——`**` 把字典拆成关键字参数。
4. 工具名字（name）和参数（arguments），缺一个程序就没法执行。
