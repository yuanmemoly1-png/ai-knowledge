# 小白课：MCP 万能插座（慢速版）

上一课：[[小白课-Agent记忆]]

> [!note] 这节课学什么
> 一个比喻用到底：你家里那抽屉配不上的充电线——苹果一种口、安卓一种口、老设备又一种口。AI 工具的世界以前就是这样：每个 AI 应用接每个工具，都要专门做一个"转接头"。
> **MCP** 就是给 AI 和工具之间定的"USB-C 标准"。这节课 5 步：先看没有标准有多惨（M×N 问题），再看统一插口怎么省活，然后认识三个角色，最后看一眼真实的配置文件。

---

## 第 1 步：没有标准的日子——M×N 问题

假设有 3 个 AI 应用、4 种工具（查天气、读文件、查数据库、发邮件）。没有统一标准时，每个应用想接每个工具，都得专门写一个对接：

```text
应用A ──┬── 转接头 ── 查天气
        ├── 转接头 ── 读文件
        ├── 转接头 ── 查数据库
        └── 转接头 ── 发邮件
应用B ──┬── …… 又是 4 个转接头
应用C ──┬── …… 再来 4 个
```

用代码算一下这笔账：

```python
apps = ["Chat桌面版", "编程助手", "笔记软件"]
tools = ["查天气", "读文件", "查数据库", "发邮件"]
print(f"没有标准：{len(apps)} 应用 × {len(tools)} 工具 = {len(apps)*len(tools)} 个转接头")
print(f"有了MCP：{len(apps)} 个插头 + {len(tools)} 个插座 = {len(apps)+len(tools)} 件活")
```

真实输出：

```text
没有标准：3 应用 × 4 工具 = 12 个转接头
有了MCP：3 个插头 + 4 个插座 = 7 件活
```

3×4=12 还是小事。真实世界几百个应用、几千个工具，乘法直接爆炸。这就是 **M×N 问题**：适配工作量是**乘**出来的。

## 第 2 步：有了 MCP——统一插口，乘法变加法

MCP 说：都别各做各的了。**工具那边统一做成标准插座，应用这边统一做成标准插头**，谁来都是即插即用：

```text
应用A ─┐
应用B ─┼── 统一插口（MCP）──┬── 查天气
应用C ─┘                    ├── 读文件
                            ├── 查数据库
                            └── 发邮件
```

上一步的输出已经算过了：12 件活变 7 件活。更妙的是**新增工具时**：再做一个标准插座就行，所有应用立刻能用——不用回去改任何一个应用。

> [!warning] MCP 不是工具本身
> 新手常把 MCP 理解成"一个能查天气的工具"。不对——MCP 是**插口标准**，查天气的活还是工具自己干的。MCP 只规定"应用和工具怎么对话"，就像 USB-C 只规定插口形状，不规定电流去哪。

## 第 3 步：三个角色，一张表看懂

MCP 的世界里有三个角色：

| 角色 | 大白话 | 对应现实 |
| --- | --- | --- |
| **Host（宿主）** | 用电器的房间，你直接用的那个 AI 应用 | Claude 桌面版、Cursor、Kimi CLI |
| **Client（客户端）** | 房间墙上的插头，Host 体内负责按标准说话的部分 | 应用内置，不用你管 |
| **Server（服务器）** | 标准插座，把某个工具/数据源按标准暴露出来 | 别人写好的天气 server、文件 server |

时序图（和 [[小白课-工具调用]] 那张图是同一个骨架，只是中间隔了标准插口）：

```text
你            Host(应用)          MCP Server(插座)
│               │                    │
│──"北京天气?"─►│                    │
│               │──标准格式询问─────►│ "你有啥工具？" "get_weather"
│               │──标准格式调用─────►│ 执行查天气
│               │◄──标准格式结果─────│
│◄──最终答案────│                    │
```

## 第 4 步：统一插口什么感觉——代码演示

没有 MCP 时，每个工具的调用方式可能千奇百怪；有了统一标准，**不管背后是哪个 server，调用方式都长一个样**：

```python
def call_tool(server, tool_name, **args):
    """统一的调用入口：server名 + 工具名 + 参数"""
    servers = {"weather": {"get_weather": lambda city: f"{city}：小雨"},
               "file": {"read_file": lambda path: f"已读取 {path}"}}
    return servers[server][tool_name](**args)

print(call_tool("weather", "get_weather", city="北京"))
print(call_tool("file", "read_file", path="笔记.md"))
```

真实输出：

```text
北京：小雨
已读取 笔记.md
```

两次调用的姿势一模一样——**应用只学一种说话方式，就能指挥所有 server**。这就是"乘法变加法"在代码里的样子。

## 第 5 步：真实配置文件长什么样

给 AI 应用接一个 MCP server，实际操作就是**在配置文件里登记一行**。比如在 Claude 桌面版的配置里写：

```json
{
  "mcpServers": {
    "weather": {
      "command": "python",
      "args": ["weather_server.py"]
    }
  }
}
```

逐字段拆：

- `"mcpServers"`：所有插座的登记本。
- `"weather"`：给这个 server 起的名字（随便起，好认就行）。
- `"command": "python"`：怎么把这个 server 启动起来——这里就是"用 python 跑"。
- `"args": ["weather_server.py"]`：启动时带的参数，即跑哪个文件。

配置好重启应用，Host 就会自动启动这个 server、问它"你有啥工具"，然后模型就能用了。验证一下这段配置确实是合法 JSON：

```python
import json
config = '''
{
  "mcpServers": {
    "weather": {
      "command": "python",
      "args": ["weather_server.py"]
    }
  }
}'''
data = json.loads(config)
print("配置读出来的server名单：", list(data["mcpServers"].keys()))
```

真实输出：

```text
配置读出来的server名单： ['weather']
```

> [!warning] 改配置最常见的错
> JSON 少个逗号、多了个尾逗号、引号不成对，应用直接不识别还不一定报错提示。改完先用 `json.loads` 或在线 JSON 校验工具过一遍。报 `JSONDecodeError` 去查 [[新手报错速查]]。

## 最关键的一句

> [!important]
> **MCP 是 AI 和工具之间的统一插口：工具做成标准 Server，应用做成标准 Host，适配从 M×N 个转接头变成 M+N 件活，接新工具只需在配置文件里登记一行。**

## 大白话翻译表

| 术语 | 大白话 |
| --- | --- |
| MCP | Model Context Protocol，AI 界的 USB-C 标准 |
| M×N 问题 | 没标准时，应用×工具=乘法爆炸的适配量 |
| Host 宿主 | 你用的 AI 应用（用电器） |
| Client 客户端 | Host 体内按标准说话的插头 |
| Server 服务器 | 按标准暴露工具的插座 |
| `mcpServers` | 配置文件里的插座登记本 |
