# 小白课：实战工具调用（Function Calling）

上一课：[[小白课-实战流式与结构化]]

> [!note] 这节课学什么
> 大模型其实**不会查天气、不会算最新的账**——它只会"递纸条"：告诉你"请帮我调用某个函数"。
> 这节课手把手走完 Function Calling 全流程：**写函数 → 写说明书 → 模型要工具 → 程序执行 → 结果回传 → 最终回答**。
> 全流程逻辑已用假模型真实运行验证过；换真 Key 就能跑真的（**需替换你的 Key 后运行**）。

---

## 第 1 步：先想清楚一件事——AI 不干活的

你问"北京天气怎么样"，AI 自己查不了。真实分工是：

1. AI 看你的问题 + 你给的**工具说明书**，说："请调用 `get_weather`，参数 `北京`"
2. **你的程序**真的去执行函数，拿到结果
3. 程序把结果塞回聊天记录，AI 看着结果说出人话

AI 是动脑不动手的指挥官，你的 Python 才是干活的。

## 第 2 步：写一个假天气函数

就是你学过的普通函数（用假数据，不接真天气接口，先跑通流程）：

```python
def get_weather(city):
    data = {"北京": "晴，25°C", "上海": "小雨，20°C", "广州": "多云，30°C"}
    return data.get(city, f"没有{city}的数据")
```

## 第 3 步：tools——给 AI 看的"工具说明书"

光写函数没用，AI 看不见你的代码。要写一份**说明书**告诉它"有什么工具、怎么填参数"：

```python
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "查询指定城市的天气",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {"type": "string", "description": "城市名，比如：北京"},
                },
                "required": ["city"],
            },
        },
    }
]
```

逐字段翻译：

- `name`：函数名，**必须和你写的函数同名**
- `description`：这个工具是干嘛的——AI 靠这句话决定要不要用它，写清楚！
- `parameters`：参数表，JSON 格式。`properties` 里每个参数一行说明
- `required`：哪些参数必填

## 第 4 步：第一次请求——AI 递回一张纸条

把问题和说明书一起发出去：

```python
messages = [{"role": "user", "content": "北京今天天气怎么样？"}]
response = client.chat.completions.create(
    model="deepseek-chat", messages=messages, tools=tools)
msg = response.choices[0].message

if msg.tool_calls:
    call = msg.tool_calls[0]
    print("模型说：请调用函数", call.function.name)
    print("参数是：", call.function.arguments)
```

✅ 看到这个就对了（本逻辑已真实运行验证）：

```text
模型说：请调用函数 get_weather
参数是： {"city": "北京"}
```

注意：AI **没有查天气**，它只是填好了"调用单"：`call.function.name` 是函数名，`call.function.arguments` 是 JSON 字符串形式的参数。

## 第 5 步：程序执行 + 结果回传 + 最终回答（完整代码）

接着第 4 步往下写（`if` 这行和第 4 步是同一个，照抄对齐）：

```python
if msg.tool_calls:
    call = msg.tool_calls[0]
    args = json.loads(call.function.arguments)   # 参数字符串 → 字典
    result = get_weather(args["city"])           # 你的程序真的执行
    print("程序真的执行了，结果：", result)
    messages.append(msg)                          # AI 的纸条也存进记录
    messages.append({"role": "tool", "tool_call_id": call.id, "content": result})

    response2 = client.chat.completions.create(
        model="deepseek-chat", messages=messages, tools=tools)
    print("最终回答：", response2.choices[0].message.content)
```

三个关键点：

1. `json.loads` 把参数从字符串变字典（上节课学的）
2. 新增一种 role：`"tool"`——工具的执行结果，必须带上 `tool_call_id`（哪张纸条的答案）
3. 第二次调用，AI 看着结果组织语言

✅ 看到这个就对了（全流程已用假模型真实运行验证）：

```text
程序真的执行了，结果： 晴，25°C
最终回答： 北京今天晴，气温25°C，适合出门玩！
```

> [!warning] 别忘了文件顶部
> 完整代码还需要 `import json`、上节课的 `client`，以及第 2、3 步的函数和 tools。从本课第 2 步开始按顺序拼接就是一个完整可跑的脚本。

## 最关键的一句

> [!important]
> **Function Calling = AI 填"调用单"（tool_calls），你的程序执行函数，结果以 role="tool" 回传，AI 再说人话——AI 动脑，程序动手。**

## 大白话翻译表

| 术语 | 大白话 |
| --- | --- |
| Function Calling | AI 递纸条叫你的程序干活 |
| `tools` | 工具说明书，告诉 AI 有什么可用 |
| `tool_calls` | AI 填好的调用单 |
| `arguments` | 调用单上的参数（JSON 字符串） |
| `role="tool"` | 工具执行结果塞回聊天记录 |
| `tool_call_id` | 纸条编号，结果要对号入座 |

## 检查一下

1. AI 返回 `tool_calls` 时，它自己已经查完天气了吗？
2. `call.function.arguments` 是什么类型？怎么用？
3. 工具执行的结果，以什么 role 塞回 messages？为什么还要带 `tool_call_id`？
4. 说明书里 `description` 写得太随便，会有什么后果？

<details>
<summary>点我看答案</summary>

1. 没有。它只是填了调用单（函数名 + 参数），真正执行的是你的程序。
2. JSON 字符串；用 `json.loads` 转成字典后按键取值，如 `args["city"]`。
3. `role="tool"`；`tool_call_id` 标明这是哪一次调用的结果，AI 可能对不上号。
4. AI 可能不知道该什么时候用这个工具，或用错参数——description 是 AI 选择工具的唯一依据。
</details>
