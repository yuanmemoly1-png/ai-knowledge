# 小白课：部署上线（慢速版）

上一课：[[小白课-Git存档术]]

> [!note] 这节课学什么
> 你的程序在自己电脑上跑得好好的——但别人用不了。**部署上线**就是把它搬出去，让全世界都能访问。这节课：
> - 本地 vs 线上的区别
> - 三个新词：服务器、域名、部署
> - 亲手写一个真正能跑的 FastAPI 小后端（本地验证）
> - 从本地到上线的概念流程（4 步）
>
> 这是开发名词篇最后一课，也是小白课堂的毕业课。

---

## 一句定义

**部署上线 = 把程序从你自己的电脑，搬到一台 24 小时开机的电脑上，让任何人随时能访问。**

## 第 1 步：本地 vs 线上

用餐厅打最后一个比方：

| | 本地（你的电脑） | 线上（部署之后） |
| --- | --- | --- |
| 像什么 | 在自家厨房试菜 | 正式开店迎客 |
| 谁能用 | 只有你自己 | 任何人，随时 |
| 电脑关了 | 程序就停了 | 不行，得 24 小时开着 |

你之前运行的每段 Python，都是"自家厨房"。要开店，先得认识三个新词。

## 第 2 步：三个新词

- **服务器**：一台 24 小时开机的电脑，放在专业机房里。你的程序搬去的就是它。"租服务器"像租店面。
- **域名**：服务器的门牌号。服务器的真实地址是一串数字（如 `43.128.x.x`），记不住；域名（如 `mycafe.com`）是给人看的名字，付钱注册一个，指到你的服务器。
- **部署**：把代码搬上服务器、装好环境、让它跑起来并保持不死的整个过程。

## 第 3 步：先在本地写一个真的能跑的小后端

用 **FastAPI**——Python 里最流行的"开餐厅"工具，几行代码就能让后端立起来。新建 `app.py`：

```python
from fastapi import FastAPI

app = FastAPI()

menu = {"宫保鸡丁": 38, "米饭": 2}

@app.get("/menu")
def get_menu():
    return menu

@app.get("/order")
def order(dish: str):
    if dish in menu:
        return {"ok": True, "msg": dish + " 下单成功"}
    return {"ok": False, "msg": "没这道菜"}
```

逐行翻译（全是旧知识）：

- `app = FastAPI()`：开一家餐厅（后端）
- `@app.get("/menu")`：在菜单上登记一道"菜"——**GET 方式、地址 `/menu`**（就是 [[小白课-API服务员]] 学的那个菜单！）
- 下面的函数：客人点这道"菜"时后端干什么，**返回的字典就是端出去的回话**
- `dish: str`：客人点单时要递的参数（`?dish=宫保鸡丁`）

本地跑起来：`pip install fastapi uvicorn`，然后 `uvicorn app:app`，浏览器打开 `http://127.0.0.1:8000/menu` 就能看到菜单。

上面的代码我用 FastAPI 自带的测试工具真实验证过：

```text
GET /menu                → 200 {'宫保鸡丁': 38, '米饭': 2}
GET /order?dish=宫保鸡丁  → 200 {'ok': True, 'msg': '宫保鸡丁 下单成功'}
```

## 第 4 步：从本地到上线，概念 4 步

本地能跑了。搬上线要做的事：

```text
① 租一台服务器（阿里云/腾讯云，最便宜的就行，约 ¥40/月）
② 把代码传上去（还记得 [[小白课-Git存档术]] 吗？git push 到 GitHub，服务器上 git pull 拉下来）
③ 在服务器上装环境、启动程序（pip install + uvicorn，和本地一模一样）
④ 注册域名，指到服务器——别人输入 mycafe.com 就能点你的"菜"
```

每一步都有现成教程，轮到自己做的时候照 [[部署与上线]] 详细笔记走。**今天只要看懂这张图。**

> [!warning] 新手常见误会
> "上线需要很高深的技术"——其实 90% 是**重复你本地做过的事**，只是换了一台电脑。真正的新东西只有租服务器和绑域名，都是点鼠标的活儿。卡在命令报错时先查 [[新手报错速查]]。

## 第 5 步：不想租服务器？还有省事的路

现在很多平台（Vercel、Render、各类云托管）帮你把 ①③④ 打包做了：你把代码 push 到 GitHub，它自动部署，还送一个临时域名。第一次练手推荐这条路，**先体验"上线了"的感觉，再回头补服务器知识**。

## 第 6 步：上线不是终点

店开张了，之后的日子是循环这三件事：

```text
看（用户反馈、报错日志）→ 改（本地改代码）→ 再部署（push → 服务器 pull）
```

所以你在这几课学的东西全串起来了：**Git 存档**让"改"有退路，**数据库**让线上的账不丢，**API 文档**让前端和后端对得上。一套闭环。

## 最关键的一句

> [!important]
> **部署上线 = 把程序搬到 24 小时开机的服务器上，绑个好记的域名。流程：本地跑通 → push 到 GitHub → 服务器拉下来跑 → 域名指过去。**
