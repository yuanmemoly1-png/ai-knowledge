# 小白课：微调 Fine-tuning（慢速版）

上一课：[[小白课-幻觉与上下文窗口]]

> [!note] 这节课学什么
> 改造接话人一共三招，前面学了两招：**纸条上写叮嘱（Prompt）**、**给他参考书（RAG）**。这节课是第三招，也是最重的一招：**微调——直接改模型本身**。
> - 微调到底在干什么
> - 三招对比，什么时候用哪招
> - 什么时候**千万别**微调

---

## 第 1 步：微调到底是什么

一句大白话定义：**微调 = 在训练好的模型上，用你自己的例题再训练一小段，把新习惯"练进骨子里"。**

回忆 [[小白课-LLM大语言模型]]：模型出厂前"训练"过一次，读全世界的书。微调是在这个成品基础上**继续训练一小会儿**，教材是你准备的几百上千条"问题 + 标准答案"。

关键区别要抓住：

- Prompt 和 RAG：**他这个人没变**，只是你每次递的纸条不同
- 微调：**他这个人变了**——不用叮嘱，他也照新规矩做

打个比方收口：Prompt 是每次上班前领导叮嘱你两句，RAG 是桌上放本手册随查随用，微调是你**真的去上了三个月培训班**——习惯长在你身上了，领导不在也照做。

## 第 2 步：微调教材长什么样

教材就是一大批"例题对子"，一行一条（真实格式是 JSONL，一行一个 JSON）：

```python
import json
教材 = [
    {"用户说": "我要投诉物流太慢", "标准回答": "非常抱歉，我马上帮您查询物流进度。"},
    {"用户说": "能便宜点吗", "标准回答": "理解您，现在下单可用新人券立减20元。"},
]
for 例题 in 教材:
    print(json.dumps(例题, ensure_ascii=False))
```

输出：

```text
{"用户说": "我要投诉物流太慢", "标准回答": "非常抱歉，我马上帮您查询物流进度。"}
{"用户说": "能便宜点吗", "标准回答": "理解您，现在下单可用新人券立减20元。"}
```

想象你准备了 1000 条这样的"用户说 → 客服标准话术"，微调之后，**他不用任何叮嘱，开口就是这个语气、这套流程**。这是 Prompt 写三页规矩也做不到的稳定性。

注意教材的文件格式：**每行一个完整的 JSON**，这叫 JSONL，是微调教材的标准长相。你现在不用会写，认识就行。

> [!warning] 教材质量比数量更要命
> 例题里写错的答案，他照单全收——**练进去什么，以后就变成什么**，烂例题比没例题更糟。另外例题太少或太雷同会"过拟合"：他只背下了这几道题，换个问法就懵。

好例题和烂例题的区别：

| 好例题 ✅ | 烂例题 ❌ |
| --- | --- |
| 答案准确、风格统一 | 答案本身有错 |
| 覆盖各种问法 | 几十条都是同一句换个说法 |
| 来自真实业务对话 | 拍脑袋瞎编的对话 |

## 第 3 步：三招对比（纸条 / 参考书 / 培训班）

| | Prompt 递纸条 | RAG 参考书 | 微调 培训班 |
| --- | --- | --- | --- |
| 改的是什么 | 这次的纸条 | 递的资料 | **模型本身** |
| 擅长解决 | 定角色、定格式、定规矩 | 他不知道的知识（私有/最新） | 稳定的语气、格式、流程 |
| 成本 | 几乎为零，随时改 | 低，资料更新即生效 | 高：备教材、花钱训练、要等 |
| 知识更新 | 改纸条就行 | 换资料就行 | **要重新训练** |

选型口诀（从上到下，能用前面的就不用后面的）：

1. **规矩和格式问题** → 先写 Prompt
2. **他不知道的知识** → 上 RAG
3. **上面两招都试了，风格/格式还是不稳定** → 才考虑微调

为什么是这个顺序？因为成本一路飙升、灵活性一路下降：纸条改起来零成本，换资料也很简单，微调一次就是一笔钱加一段等待，练错了还得重来。**越重的招，越要放到最后用。**

## 第 4 步：什么时候千万别微调

这是这节课最重要的部分。四种情况，微调是**错误答案**：

1. **想让他"学会新知识"** ❌
 公司文档、产品信息常变，微调一次就固化一次，改个价格都得重训。这是 RAG 的活（[[小白课-RAG开卷考试]]）。
2. **Prompt 还没认真试过** ❌
 80% 的"他不听话"是纸条没写好。先把三口诀（角色/任务/格式，见 [[小白课-Prompt提示词]]）用到位。
3. **手里只有几十条例题** ❌
 微调要几百上千条高质量例题才有效果，几十条约等于没练。
4. **想修幻觉** ❌
 微调改的是"说话方式"，改不了"不懂也敢编"的天性（[[小白课-幻觉与上下文窗口]]）。

> [!warning] 一句话总结这块
> **微调管"怎么说"，不管"知道什么"。**拿微调去补知识，是新手在这三招里最常犯的错。

## 第 5 步：什么时候可以考虑微调

也说实话，它有自己的地盘：

- **固定输出格式**：比如永远输出特定结构的 JSON，Prompt 偶尔翻车，微调能钉死
- **固定风格语气**：客服话术、特定的写作腔调，要几百条对话都稳定一致
- **例题足够多**：手里攒了几百上千条高质量"问题→标准答案"

就算符合，顺序依然是：**先 Prompt → 再 RAG → 都不行，最后微调。**

> [!note] 个人玩家的现实情况
> 微调一般在模型厂商的平台或开源框架上做，一次几美元到几百美元不等。对学习和个人项目来说，**Prompt + RAG 几乎能覆盖全部需求**——微调这招先记住概念，真到"格式必须钉死"的产品场景再回来翻这一课。

## 最关键的一句

> [!important]
> **微调是改模型本身：Prompt 管规矩、RAG 管知识、微调管风格；能用前两招解决的，千万别微调。**
