# 小白课：实战流式与结构化输出

上一课：[[小白课-实战messages三角色]]

> [!note] 这节课学什么
> 你已经会让 AI 一次性把话说完。这节课学两个"接话姿势"：
> - **流式输出**：像打字机一样一个字一个字蹦出来（网页版 AI 那种效果）
> - **结构化输出**：逼 AI 只回 JSON，让你的程序能接住结果继续干活
>
> 代码接着上两节课的 `client` 用（**需替换你的 Key 后运行**，输出是示意）。

---

## 第 1 步：流式是什么——打字机 vs 憋大招

普通调用：AI **全部想完**才把整段话一次性给你，问大问题要等好几秒。

流式输出：AI 想到一点吐一点，你的程序**边收边打印**——就是你在网页版看到的打字机效果。

区别只在调用时多写一个 `stream=True`。

## 第 2 步：stream=True，逐块打印

```python
stream = client.chat.completions.create(
    model="deepseek-chat",
    messages=[{"role": "user", "content": "用三句话夸一夸 Python"}],
    stream=True,
)
for chunk in stream:
    piece = chunk.choices[0].delta.content
    if piece:
        print(piece, end="", flush=True)
print()
```

拆开看：

1. `stream=True` —— 返回值变成一个"能 for 循环的流水管"
2. `for chunk in stream:` —— 每来一小块，循环跑一遍
3. `chunk.choices[0].delta.content` —— 这一小块的文字（注意是 `delta`，不是 `message`）
4. `print(piece, end="", flush=True)` —— 不换行、立刻显示，拼出打字机效果

✅ 看到这个就对了：文字一段一段蹦出来，最后拼成完整的一段话（本逻辑已用假数据真实运行验证，逐块效果如下）：

```text
收到一块：'你好'
收到一块：'呀，'
收到一块：'很高兴'
收到一块：'见到'
收到一块：'你！'
```

> [!warning] 别写错地方
> 普通调用取 `message.content`，流式取 `delta.content`。用错会拿到 `None` 或报错。

## 第 3 步：让 AI 只回 JSON

程序跟程序打交道，要的是**规整的数据**，不是一大段客套话。办法：在提示词里下死命令。

```python
response = client.chat.completions.create(
    model="deepseek-chat",
    messages=[{"role": "user", "content": "把这句话整理成 JSON：小明，20岁，爱好打球和看书。只输出 JSON，不要任何其他文字。"}],
    response_format={"type": "json_object"},
)
raw = response.choices[0].message.content
print("模型返回的原文：", raw)
```

✅ 看到这个就对了（示意）：

```text
模型返回的原文： {"name": "小明", "age": 20, "hobbies": ["打球", "看书"]}
```

双保险：

- 提示词里写"只输出 JSON，不要任何其他文字"
- 再加 `response_format={"type": "json_object"}`（DeepSeek 支持），用 API 层面锁住格式

## 第 4 步：json.loads——把字符串变回字典

AI 回来的 JSON 本质还是一个**字符串**。用你学过的 `json.loads` 把它变成字典，程序就能用了（这段不需要 Key，可直接运行，已真实验证）：

```python
import json

raw = '{"name": "小明", "age": 20, "hobbies": ["打球", "看书"]}'
data = json.loads(raw)
print("解析前类型：", type(raw))
print("解析后类型：", type(data))
print("姓名：", data["name"])
print("第一个爱好：", data["hobbies"][0])
```

✅ 看到这个就对了：

```text
解析前类型： <class 'str'>
解析后类型： <class 'dict'>
姓名： 小明
第一个爱好： 打球
```

## 第 5 步：AI 耍赖给了废话怎么办

AI 偶尔会在 JSON 前面加句"好的！结果是："。这时 `json.loads` 直接报错（已真实运行验证）：

```text
报错了：JSONDecodeError → Expecting value: line 1 column 1 (char 0)
```

救援办法：

1. **预防**：提示词更狠一点 + 上 `response_format`
2. **兜底**：套 `try/except json.JSONDecodeError`，报错就让 AI 重答一次

这就是 [[小白课-Prompt提示词]] 说的"约束越具体，结果越听话"。

## 这节课有什么用？

- **流式**：做聊天界面、命令行助手，用户不用干等
- **JSON**：AI 的回答变成程序能处理的字典——查完天气自动存进数据库、批量整理表格、填进网页，全靠这一步。下节课的工具调用，本质上也是 AI 返回结构化数据。

## 最关键的一句

> [!important]
> **`stream=True` 让回答边想边吐（逐块取 `delta.content`）；提示词下死命令 + `response_format` 让 AI 只回 JSON，`json.loads` 一解析，程序就接住了 AI 的结果。**

## 大白话翻译表

| 术语 | 大白话 |
| --- | --- |
| 流式 stream | 打字机模式，想到一点吐一点 |
| `chunk` | 流水管里来的一小块 |
| `delta.content` | 这一小块里的文字 |
| `flush=True` | 立刻显示，别攒着 |
| JSON | 程序之间通用的"表格文字" |
| `json.loads` | 把 JSON 字符串变回字典/列表 |
| `response_format` | API 层面的格式锁 |

3. AI 返回 `'{"age": 20}'`，怎么让程序取出 `20`？
4. `json.loads` 报 `JSONDecodeError`，最常见的原因是什么？

<details>
<summary>点我看答案</summary>

1. `chunk.choices[0].delta.content`；普通调用是 `response.choices[0].message.content`（一个是 `delta`，一个是 `message`）。
2. 打印完不换行，让下一小块接在同一行后面，拼出完整句子。
3. `data = json.loads(...)` 变成字典后，`data["age"]`。
4. AI 在 JSON 前后加了废话（比如"好的！"），或格式本身不合法——预防靠提示词约束 + `response_format`，兜底靠 `try/except`。
</details>
