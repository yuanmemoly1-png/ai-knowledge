# 小白课：前端与后端（慢速版）

上一课：[[小白课-MCP万能插座]]

> [!note] 这节课学什么
> 整个第四篇，我们只用**一家小餐厅的一天**当例子。这节课先认清餐厅的两个半边：
> - **前端**：前厅——你眼睛看到、手能点到的一切
> - **后端**：后厨——你看不见，但真正的活儿都在那干
>
> 学完你能说清楚：你在 App 里点「下单」之后，到底发生了什么。

---

## 一句定义

**前端管「长什么样」，后端管「事情怎么办」。**

## 第 1 步：前端 = 前厅

你走进一家餐厅，能看到的是：桌椅、装修、菜单、服务员的笑容。这些都是**前厅**。

换成 App 也一样。你在购物 App 里能看到的都是前端：

- 商品的图片和价格
- 「加入购物车」那个按钮
- 页面的排版、颜色、动画

前端的工作就两件：**把东西摆出来给你看，把你点的按钮记下来。**

## 第 2 步：后端 = 后厨

你坐下点菜，但菜不是服务员炒的——后厨里切菜、炒菜、洗碗，你一概看不见。这些都是**后厨**。

换成 App：

- 你点「登录」，是**后端**去查你的密码对不对
- 你下单，是**后端**去扣库存、记订单
- 你账户里剩多少钱，存在**后端**那边，前端只是负责显示那个数字

后端的工作也是两件：**记住所有数据，干所有真正的逻辑。**

## 第 3 步：一次下单的完整旅程（5 步）

这节课最重要的一张图。你在 App 里点「下单宫保鸡丁」，接下来发生 5 件事：

```text
① 你（顾客）     在前厅点「下单」按钮
② 前端（前厅）   把按钮变成一张点菜单，交给服务员
③ 服务员（API）  拿着点菜单跑去后厨          ← 下一课专门讲他
④ 后端（后厨）   查库存 → 还有 → 扣掉 1 份 → 记下这笔订单
⑤ 服务员端回话   「下单成功，还剩 2 份」→ 前端把它显示在屏幕上
```

注意第 ④ 步：**真正干活的只有后端**。前端从头到尾只做「展示」和「传话」。

## 第 4 步：亲手感受一下前后端分工

下面这段代码真的能跑。前半段是"后端"（看不见的逻辑），后半段是"前端"（只负责显示）：

```python
# ===== 后端（后厨）：看不见的逻辑 =====
def chuli_dingdan(caiming, kucun):
    if kucun.get(caiming, 0) > 0:
        kucun[caiming] -= 1
        return {"ok": True, "msg": caiming + " 下单成功，还剩 " + str(kucun[caiming]) + " 份"}
    return {"ok": False, "msg": "卖完了"}

kucun = {"宫保鸡丁": 2}

# ===== 前端（前厅）：只负责把结果显示给人看 =====
jieguo = chuli_dingdan("宫保鸡丁", kucun)
print("你看到的是：", jieguo["msg"])
jieguo = chuli_dingdan("宫保鸡丁", kucun)
print("你看到的是：", jieguo["msg"])
jieguo = chuli_dingdan("宫保鸡丁", kucun)
print("你看到的是：", jieguo["msg"])
```

输出：

```text
你看到的是： 宫保鸡丁 下单成功，还剩 1 份
你看到的是： 宫保鸡丁 下单成功，还剩 0 份
你看到的是： 卖完了
```

看门道：

- `chuli_dingdan` 函数里的"查库存、扣库存"就是**后端逻辑**——用户永远看不到这几行
- `print` 那一行就是**前端**——它不管库存怎么算，只把后端给的 `msg` 摆出来
- 后端返回的是**字典**（你在 [[小白课-Python列表与字典]] 学过），前后端之间传递的数据大多长这样

## 第 5 步：前后端各自用什么语言写？

| 半边 | 常用语言 | 一句话说明 |
| --- | --- | --- |
| 前端 | HTML / CSS / JavaScript | 浏览器只认这三种，分别管结构、长相、动作 |
| 后端 | Python / Java / Go … | 跑在服务器上，什么语言都行，**Python 就是热门选择** |

对零基础的好消息：**你正在学的 Python 就是后端主力语言之一**。前端那三种以后想补再看 [[小白课-程序拆解实战]] 提到的路线，不急。

## 第 6 步：瞟一眼前端代码长什么样

不用学，只看长相。前端的"界面"是用 HTML 写的，浏览器读到它就画出按钮和文字：

```html
<h1>小小餐厅</h1>
<button>下单宫保鸡丁</button>
```

这两行在浏览器里就是一个标题 + 一个按钮。你点那个按钮，它就通过 API 把单子送去后端——又绕回第 3 步的旅程了。

> [!warning] 新手常见误会
> 「前端后端是两台电脑」——错。它们是**同一个程序的两个部分**，只是跑在不同地方：前端跑在你的手机/浏览器里，后端跑在远处的服务器上。写代码的也是同一个人都行（那叫**全栈**）。

## 最关键的一句

> [!important]
> **前端管「长什么样」（HTML/CSS/JS，跑在你手机上），后端管「事情怎么办」（Python 等，跑在服务器上）。中间的传话人叫 API。**

## 大白话翻译表

| 术语 | 大白话 |
| --- | --- |
| 前端 Frontend | 餐厅前厅，你看到和点到的界面 |
| 后端 Backend | 餐厅后厨，看不见但干真活的地方 |
| 客户端 Client | 你手里用的那个 App / 浏览器 |
| 服务器 Server | 后厨所在的那台电脑，24 小时开机 |
| 全栈 Full-stack | 前厅后厨的活都会干的人 |
| 请求 / 响应 | 点菜单递进去 / 后厨回的话 |
