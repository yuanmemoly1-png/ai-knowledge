# 费曼学习法（讲出来，才算会）

> [!note] 一句话
> **能用大白话把知识讲给别人听，才算真懂。** 讲不出来的地方，就是你的知识漏洞——找出来，回去补，再讲一遍。本库主人亲测：一次复述顶看五遍笔记。

## 四步流程

```text
① 学完一块知识（比如一节课）
      ↓
② 合上笔记，讲出来：假装讲给一个完全不懂的人听
      ↓
③ 卡壳处 = 漏洞：标记下来，回笔记/课程补这一个点
      ↓
④ 再讲一遍，直到顺溜、简单、不用术语
```

## 在本知识库里的三种用法

### 1. 每课一复述（5 分钟）
刷完一节小白课，合上讲义，把核心概念讲出来。不知道讲没讲对？**讲给 AI 听**，用模板：

> 「我刚学完 XX，我用自己的话讲一遍，你帮我挑错：……」

### 2. 出题互考（10 分钟）
让 AI 当考官，你当小老师：

> 「用费曼学习法考我 Python 的 XX 部分：你出 5-8 个由浅入深的问题，我用大白话回答，你逐条批改——讲对的盖章，讲歪的纠正，讲不出的标为我的复习重点。」

（这就是 [[学习日志]] 2026-08-07 那次"取货单"8 题复述的原版模板，照抄可用）

### 3. 讲给"空气"（碎片时间）
通勤、散步时心里默讲："列表和字典有什么区别？for 循环在干嘛？" 讲不顺的，回家翻笔记——**零成本的漏洞扫描仪**。

## 适用范围

**这套方法适用于本库所有材料**——不只是 Python：Agent 概念（"给我讲讲 MCP 是干嘛的"）、开发名词（"用餐厅讲一遍前后端"）、甚至源码拆解（"讲讲 Kimi CLI 的主循环"）都能用费曼复述检验。凡是"看懂了"的东西，都值得讲一遍验证。

## 判断"真会"的标准

| 状态 | 真相 |
| --- | --- |
| 看笔记觉得懂 | 不一定懂（熟悉感错觉） |
| 合上能讲出来 | 懂了 70% |
| 能讲给外行听懂 | 真懂 |
| 能做题 + 能讲 + 能教 | 刻进手里了 |

## 真实案例（本库主人，2026-08-07）

复述第 8 题时卡在"为什么循环字典要用 `scores[name]`"——这个卡壳暴露了"for 发的是取货单不是货"的漏洞。针对性补完后，第二天碰到 `d.items()`、双层取值全通了。**漏洞不怕暴露，怕的是藏着。**
