# 小白课：RAG 开卷考试（慢速版）

上一课：[[小白课-Embedding语义坐标]]

> [!note] 这节课学什么
> 接话人有两个硬伤：不知道你的私有资料，不知道他"毕业"之后发生的事。**RAG 的思路：别让他背，让他查——先查资料再回答，闭卷变开卷。**
> 这节课把 RAG 拆成四步：**切书 → 编号 → 查书 → 作答**，每步单独讲，最后跑一个迷你查书演示。

---

## 第 1 步：为什么需要 RAG？

先回忆两个旧知识点：

- **幻觉**（[[小白课-LLM大语言模型]] 第 4 步）：不知道的事他也敢编
- **知识过时**：他读的书截止到训练那天，之后的新闻、你公司上周的定价，他一概不知

你问他"我们公司产品 A 多少钱"，他不可能知道，但大概率照编一个数。重新训练一个模型让他"学会"你的资料？一次训练几百万起步，还得几个月——**为改个价格重新训练，等于为改菜单把厨子回炉重造**。

RAG 的思路朴素得多：**资料不进他脑子，回答前把相关那几页查到、连同问题一起递给他："照这个答。"**

## 第 2 步：切书（chunking）

第一步预处理：**把你的资料切成一小段一小段**。

为什么不能整本塞给他？两个原因：他桌面装不下（上下文窗口，下一课讲）；而且整本里 99% 和问题无关，塞进去只会干扰他。

切多大？经验值：**一段话说清一件事**（几百字左右）。太短断了上下文，太长找不准。切好的每一小段，就像书里撕下来的一页。

## 第 3 步：编号（Embedding 入库）

每一页怎么"编号"才能以后找得到？用上一课学的：**把每一页变成 Embedding 坐标，存进向量数据库**。

```
"产品A售价199元…"  →  [0.21, 0.87, ...]  →  存进仓库
"退货政策：7天内…"  →  [0.55, 0.12, ...]  →  存进仓库
```

这个仓库叫**向量数据库**，它和普通仓库的区别：普通仓库按名字找，它按"**意思近不近**"找。这一步只做一次，资料更新了再补。

## 第 4 步：查书（retrieval）

用户提问的那一刻：

1. 把**问题也变成坐标**（同一个 Embedding 模型）
2. 去向量仓库里找**离问题坐标最近的几页**

跑一个迷你版感受一下（真实仓库用余弦相似度，这里用"包含关键词"代替，原理一样是"匹配"）：

```python
pages = [
    "产品A售价199元，全国包邮。",
    "产品B售价299元，运费另算。",
    "退货政策：签收后7天内可无理由退货。",
]
question = "产品A"
for i, p in enumerate(pages):
    if question in p:
        print(f"翻到第 {i} 页：{p}")
```

输出：

```text
翻到第 0 页：产品A售价199元，全国包邮。
```

**这就是"查"：问题进来，最相关的那页被翻出来。**真实的 RAG 只是把这个匹配从"关键词"升级成了"语义坐标"。

> [!warning] 容易踩的坑
> **查错书 = 答错题。**查书这步翻出来的是"产品B"那页，他照着答就是错的。所以做 RAG 系统，一半功夫都花在"怎么查得准"上（切片大小、一次取几页）。

## 第 5 步：作答（拼纸条）

最后一步，把查到的页和问题**拼成一张大纸条**，用 [[小白课-Prompt提示词]] 学的格式递给他：

```python
资料 = "产品A售价199元，全国包邮。"
问题 = "产品A多少钱？"
prompt = f"请只根据下面这段资料回答问题。\n资料：{资料}\n问题：{问题}"
print("---拼好的纸条---")
print(prompt)
```

输出：

```text
---拼好的纸条---
请只根据下面这段资料回答问题。
资料：产品A售价199元，全国包邮。
问题：产品A多少钱？
```

注意纸条开头那句"**请只根据下面这段资料回答**"——这句话是 RAG 的灵魂：把他从"凭记忆瞎编"约束成"照资料念"。他不用会，只要会读。

## 第 6 步：这和微调有什么区别？（引子）

你可能会问：想让他"学会"公司资料，不是还有微调吗？一句话区分：

- **RAG = 给他发参考书**：知识在书里，随时可换，查得到才答得出
- **微调 = 送他去培训班**：知识练进他骨子里，但改起来要重训

绝大部分"让他知道我的资料"的需求，**用 RAG 就够了**，微调是另一回事——最后一课 [[小白课-微调Fine-tuning]] 细讲。

## 第 7 步：把四步串起来看一遍

```text
你的资料 → 切书 → 每页变坐标入库 ────────┐
                                          ↓ 查书
用户提问 → 问题变坐标 → 找最近的几页 → 拼进大纸条 → 模型照资料作答
```

四步里只有"查书"和"作答"发生在用户提问的瞬间；**切书和编号是提前一次性做好的**。这就是为什么 RAG 系统回答前总要"转圈"一秒——它在翻书。

## 最关键的一句

> [!important]
> **RAG = 切书 → 编号（Embedding）→ 查书（找最近）→ 作答（资料+问题拼成一张纸条，"只根据资料回答"）。**

## 大白话翻译表

| 术语 | 大白话 |
| --- | --- |
| RAG 检索增强生成 | 先查资料再回答，开卷考试 |
| chunking 切片 | 把资料切成一小段一小段 |
| 向量数据库 | 按"意思近"找页的仓库 |
| retrieval 检索 | 问题变坐标，找最近的几页 |
| 增强 generation | 把查到的页拼进纸条再让他答 |

## 检查一下

1. RAG 解决了 LLM 的哪两个硬伤？
2. 为什么不能把整本资料直接塞给模型？
3. "查书"那一步用的是什么技术找相关的页？
4. 拼纸条时开头那句"请只根据资料回答"有什么用？

<details>
<summary>点我看答案</summary>

1. 幻觉（不知道也敢编）和知识过时/缺私有知识。
2. 上下文窗口装不下，且大量无关内容会干扰回答。
3. Embedding：把问题和每页都变成坐标，找距离最近的页。
4. 把模型从"凭记忆瞎编"约束成"照资料作答"，大幅降低幻觉。
</details>
