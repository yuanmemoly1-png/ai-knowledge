# 小白课：全栈前后端合体（最小全栈应用）

上一课：[[小白课-全栈FastAPI后端]]

> [!note] 这节课学什么
> 前四节课的两半**今天合体**：FastAPI 不再只返回 JSON，而是**直接把网页端给浏览器**；网页上的按钮用 `fetch` 回头找自己的后端要数据。
> 按 4 步走：看懂合体结构 → 一个 `main.py` 装下网页 + API → `uvicorn` 开店 → 点按钮看前后端对话。
> 这就是"全栈"的最小形态（代码已用 `fastapi.testclient` + `node --check` 双重验证，放心照抄）。

---

## 第 0 步：合体后长什么样

回忆一下分工：

- **前端**（HTML + CSS + JS）：顾客看到的店面
- **后端**（FastAPI）：后厨，做菜（处理数据）
- **fetch**：服务员，前后端之间跑堂传话

这节课一个文件搞定：**FastAPI 既端网页（访问 `/`），又端数据（访问 `/api/hello`）**——网页上的按钮通过 fetch 找 `/api/hello` 要一句话，显示出来。

## 第 1 步：一个 main.py 装下全部

新建 `main.py`（或清空旧的），整段复制（**已验证**：`/` 返回完整网页、`/api/hello` 返回正确 JSON，均用 `fastapi.testclient` 实际请求通过）：

```python
from fastapi import FastAPI
from fastapi.responses import HTMLResponse

app = FastAPI()

# 整个网页存在一个字符串里，访问 / 就把它发给浏览器
HTML_PAGE = """
<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <title>我的第一个全栈应用</title>
</head>
<body>
    <h1>前后端合体啦</h1>
    <button id="btn">点我，问后端好</button>
    <p id="answer">（后端的话会出现在这里）</p>

    <script>
        const btn = document.getElementById("btn");
        btn.onclick = async function () {
            // 第 1 步：发请求 —— 向自己家的 /api/hello 要数据
            const response = await fetch("/api/hello");
            // 第 2 步：等响应 —— 拆开包裹，把 JSON 转成 JS 对象
            const data = await response.json();
            // 第 3 步：显示 —— 把数据写到页面上
            document.getElementById("answer").textContent = data.message;
        };
    </script>
</body>
</html>
"""

@app.get("/", response_class=HTMLResponse)
def home():
    return HTML_PAGE

@app.get("/api/hello")
def hello():
    return {"message": "你好！我是后端，你的请求我收到啦"}
```

拆开看新东西：

- `HTML_PAGE = """..."""` —— 三引号字符串，把**整个网页**存进一个 Python 变量（里面就是你前三课学的 HTML + JS）
- `response_class=HTMLResponse` —— 告诉 FastAPI"这次端的是网页，不是 JSON"，浏览器才会把它画成页面
- 两个 `@app.get` —— 一家店两个窗口：`/` 端网页，`/api/hello` 端数据

> [!warning] 真实项目不这么装
> 网页塞在 Python 字符串里只是为了**一个文件看懂全貌**。真实项目里 HTML 会放在单独的文件/文件夹里（FastAPI 用 `StaticFiles` 或模板来管），思路完全一样，见 [[全栈项目实战]]。

## 第 2 步：逐行讲 fetch 三步

网页里那段 JS 是本课的灵魂。`fetch` 就是**浏览器里的服务员**，它的活分三步，代码里已用注释标出：

**第 1 步：发请求**

```js
const response = await fetch("/api/hello");
```

服务员拿着单子跑去 `/api/hello` 窗口。`await` = "**在这等着**，后端回话了我再往下走"（后端再快也要花时间，不能干等卡死页面）。

**第 2 步：等响应（拆包裹）**

```js
const data = await response.json();
```

后端端回来的是 JSON 文字（`{"message": "你好！..."}`）。`.json()` 把它**拆开转成 JS 对象**，这样 `data.message` 就能取出里面的话。

**第 3 步：显示**

```js
document.getElementById("answer").textContent = data.message;
```

上节课的老招式：抓住 `<p id="answer">`，把后端的话写上去。

顺口溜：**fetch 发请求 → await 等包裹 → .json() 拆包裹 → getElementById 贴上墙。**

## 第 3 步：点火，看前后端对话

终端里运行（店还开着的话先 `Ctrl + C` 关火）：

```bash
uvicorn main:app --reload
```

浏览器打开 `http://localhost:8000`。

✅ 看到这个就对了：页面上有大标题"前后端合体啦"和一个按钮。**点按钮**——"（后端的话会出现在这里）"变成"你好！我是后端，你的请求我收到啦"。

这一下发生了什么（值得默念一遍）：

1. 浏览器访问 `localhost:8000/` → FastAPI 把网页端过来（前端到店）
2. 你点按钮 → JS 的 `fetch` 跑去 `localhost:8000/api/hello`（服务员跑堂）
3. FastAPI 返回 JSON（后厨出菜）
4. JS 把话写上页面（服务员上菜）

**对照实验**：直接访问 `http://localhost:8000/api/hello`，看到的是生 JSON；而按钮帮你在页面里完成了"要数据 + 展示"。这就是所有网站的基本套路。

> [!warning] 分不清哪段跑在哪？记住一句话
> Python 代码跑在**你的终端里**（后端），HTML/JS 跑在**浏览器里**（前端）。F12 的 Console 看 JS 报错，终端窗口看 Python 报错——**报错在哪边，人就往哪边查**。

## 第 4 步：报错救援表

| 报错 / 现象 | 意思 | 解法 |
| --- | --- | --- |
| 访问 `/` 看到一坨网页源码而不是页面 | 忘了 `response_class=HTMLResponse` | 加上它，浏览器才知道要画成页面 |
| 点按钮没反应 | JS 出错 | F12 看 Console；先检查 `id="btn"`、`id="answer"` 对没对上 |
| Console 报 `404 (Not Found)` | fetch 的地址和后端路由对不上 | JS 里 `fetch("/api/hello")` 和 Python 里 `@app.get("/api/hello")` 必须一字不差 |
| Console 报 `Failed to fetch` | 店没开 | 终端里 `uvicorn main:app --reload` 还开着吗 |
| 终端报红字 | Python 后端出错 | 看终端报错行号，对照 `main.py` 改 |

更多排查套路见 [[新手报错速查]]。

## 最关键的一句

> [!important]
> **全栈 = 前端（浏览器里的 HTML/JS）+ 后端（终端里的 FastAPI）+ fetch 跑堂：`@app.get("/")` 端网页、`@app.get("/api/...")` 端数据，按钮 fetch 三步走——发请求、拆 JSON、贴上墙。**
