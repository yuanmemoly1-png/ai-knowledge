# 小白课：Agent 传纸条循环（慢速版）

上一课：[[小白课-微调Fine-tuning]]（从这里开始进入 Agent 篇）

> [!note] 这节课学什么
> 一个比喻用到底：LLM 是个**关在没有窗户的房间里的人**，特别会写字，但出不了门——不能上网、不能查天气、不能碰你的文件。你和他唯一的交流方式是**从门缝塞纸条**。
> 这节课搞清楚一件事：门外再加一个**跑腿小哥**，定一套**暗号**，这个"会聊天的房间"就变成能动手做事的 **Agent**。全程 6 步，每步都有能跑的代码。

---

## 第 1 步：先看清 LLM 的本事——只看纸条、写纸条

LLM（大语言模型）的本质就是一个函数：**一堆纸条塞进去，一张纸条吐出来**。我们用 Python 造一个"假 LLM"来模拟：

```python
def fake_llm(notes):
    """假装是LLM：只会看最后一张纸条，然后回一张"""
    last = notes[-1]
    if "查天气结果" in last:
        return "北京今天小雨，26度，记得带伞。"
    return "TOOL:get_weather:北京"      # 看不懂就写暗号（第3步讲）
```

它不会联网，不会查文件，连"今天几号"都不知道——**它唯一的本事就是根据纸条内容回纸条**。真实的 LLM 也一样，只是回的纸条更长更聪明。

## 第 2 步：门外的跑腿小哥——一个普通函数

房间里的人出不来，但门外有你写的程序，什么都能干。比如查天气：

```python
def get_weather(city):
    """门外的跑腿小哥：真的去干活"""
    return f"查天气结果：{city} 小雨，26度"
```

这就是**工具（Tool）**：一个普通的 Python 函数，能联网、能读文件、能按电梯。LLM 碰不到它，但你的程序能。

## 第 3 步：定暗号——LLM 怎么"喊"跑腿干活

LLM 只会写字，所以它"想用工具"的方式只能是：**在纸条上写一个约定好的暗号**。我们和它约定：

```text
TOOL:工具名:参数
```

比如它回 `TOOL:get_weather:北京`，意思就是"我答不上来，麻烦跑腿的去查一下北京的天气"。

门外的程序每收到一张纸条，先检查：**开头是 `TOOL:` 吗？** 是 → 照着暗号干活；不是 → 这就是给用户的最终答案。

> [!warning] 暗号必须提前约定好
> 新手最容易误解的一点：**暗号不是 LLM 天生会的，是你在提示词里教它的**。你不告诉它格式，它就瞎写，程序对不上暗号就会当成最终答案直接收工。真实框架里这套格式叫 function calling 的 schema，下一课 [[小白课-工具调用]] 细讲。

## 第 4 步：一步一图解——完整一轮纸条时序

把前面三块拼起来，问一句"北京今天天气怎么样？"，全程长这样：

```text
你                房间里的LLM            门外的程序(跑腿)
│                     │                     │
│──纸条①────────────►│                     │
│  "北京今天天气?"     │                     │
│                     │──纸条②────────────►│
│                     │  "TOOL:get_weather  │ 程序看到暗号！
│                     │   :北京"            │
│                     │                     │──调 get_weather("北京")
│                     │                     │   真的去查
│                     │◄──纸条③─────────────│
│                     │  "查天气结果:        │ 结果塞回门缝
│                     │   北京 小雨,26度"    │
│◄──纸条④────────────│                     │
│  "北京今天小雨,      │ 这次没写暗号=        │ 循环结束
│   26度,记得带伞"     │ 最终答案            │
```

数一下：LLM 回了**两次**纸条（②和④），跑腿干了**一次**活（③之前）。关键在程序每一圈都要判断："这张纸条是暗号还是答案？"

## 第 5 步：真跑一遍（代码 + 真实输出）

把第 1、2、3 步的代码合起来，加一个循环：

```python
notes = ["用户问：北京今天天气怎么样？"]

for i in range(3):                      # 最多转3圈，防止死循环
    reply = fake_llm(notes)
    print(f"第{i+1}圈，LLM回纸条：{reply}")
    if reply.startswith("TOOL:"):       # 看到暗号
        _, tool, arg = reply.split(":")
        result = get_weather(arg)       # 跑腿的去干活
        notes.append(result)            # 结果塞回门缝
        print(f"  跑腿小哥塞回：{result}")
    else:
        break                           # 不是暗号=最终答案，收工
```

真实输出（实际运行结果）：

```text
第1圈，LLM回纸条：TOOL:get_weather:北京
  跑腿小哥塞回：查天气结果：北京 小雨，26度
第2圈，LLM回纸条：北京今天小雨，26度，记得带伞。
```

对照第 4 步的图看：第 1 圈对应纸条②③，第 2 圈对应纸条④。代码和图严丝合缝。

> [!warning] 为什么写 `range(3)` 而不是 `while True`
> 万一 LLM 一直写暗号（比如工具老报错），循环会永远转下去，你的 API 费用会一直烧。真实 Agent 都会设**最大圈数**。这是 [[小白课-Token与计费]] 里说的"烧钱陷阱"之一。

## 第 6 步：为什么这就是 Agent Loop

回头看，这个循环就是全部秘密：

1. 把纸条塞给 LLM
2. LLM 回纸条：**直接答** 或 **写暗号要工具**
3. 是暗号 → 程序执行工具 → 结果塞回去 → 回到第 1 步
4. 不是暗号 → 输出最终答案，停

**Agent = LLM + 工具 + 这个循环。** 没有魔法。你在 [[小白课-ReAct思考行动循环]] 会看到：给这个循环加上"先想再做"的规矩，它就更稳；在 [[小白课-Agent记忆]] 会看到：纸条越攒越多怎么办。但骨架永远是这一课的循环。

## 最关键的一句

> [!important]
> **LLM 出不了房间，它"做事"的方式是写暗号纸条；门外的程序看到暗号就去执行工具、把结果塞回去——这一来一回的循环就是 Agent loop。**

## 大白话翻译表

| 术语 | 大白话 |
| --- | --- |
| Agent 智能体 | 房间里的 LLM + 门外的跑腿 + 传纸条规则 |
| Agent loop | 塞纸条→看回条→干工具→再塞，转到出答案 |
| Tool 工具 | 门外跑腿的会的活，一个普通函数 |
| 暗号 | LLM 写下的"我要用工具"的约定格式 |
| 最大圈数 | 防止循环永远转、烧光预算的保险丝 |

## 检查一下

1. LLM 想查天气时，它实际做了什么动作？（提示：它碰不到网络）
2. 门外的程序收到纸条后，第一件事是判断什么？
3. 第 5 步代码里，`break` 在什么情况下执行？
4. 为什么循环要限制最多 3 圈？

<details>
<summary>点我看答案</summary>

1. 在纸条上写约定好的暗号（如 `TOOL:get_weather:北京`），由门外的程序去真正执行。
2. 判断纸条是不是暗号（开头是不是 `TOOL:`）——是就调工具，不是就当作最终答案。
3. 当 LLM 回的纸条不是暗号，也就是给出了最终答案时。
4. 防止 LLM 一直要工具导致死循环，空烧时间和 API 费用。
</details>
