# 小白课：提示词工程进阶（慢速版）

上一课：[[小白课-Prompt提示词]]

> [!note] 这节课学什么
> 上一课的三口诀（**给角色、给任务、给格式**）是"会说话"。这一课升级成"工程化"——像搭积木一样**按模块拼提示词**，这是写 Agent、写系统提示词（几百行那种）的干活方式：
> - 提示词为什么能"拆成模块"
> - 6 类通用模块长什么样
> - 六步写作流水线（拿翻译助手完整走一遍）
> - 角色怎么定（一个角色管一个"智能体"，不是每个任务都重定）

---

## 第 1 步：为什么三口诀不够

三口诀能应付"问一句话"。但做 Agent、做系统时，提示词要写几百行，还要给不同场景反复用。这时候"想到哪写到哪"会乱成一团，必须**模块化**。

生活比喻：**提示词不是"写一封信"，是"搭一栋楼"**——

| 模块    | 比喻               |
| ----- | ---------------- |
| 身份    | 大楼的招牌和前台         |
| 环境    | 水电、位置信息          |
| 工具    | 大楼里的手（能干活的东西）    |
| 行为准则  | 员工手册（Do / Don't） |
| 项目规则  | 每层楼自己的规矩         |
| 输出与边界 | 大楼的验收标准          |

> 你上一课学的"给角色、给任务、给格式"，其实就是这 6 类模块里最常用的 3 个——现在把它们**补齐成套**。

## 第 2 步：6 类通用模块（填空模板）

| 模块 | 回答什么问题 | 写法 |
| --- | --- | --- |
| **身份** | 我是谁 | 一句话：`你是知识库整理助手。` |
| **环境** | 我在哪、现在几点 | 用变量：`工作目录是 {{cwd}}` |
| **工具** | 我有哪些手、何时用 | 列清单 + 说清场景 |
| **行为准则** | 我干活有什么规矩 | 具体到动词：`不要修改原始文件` |
| **项目规则** | 项目/用户偏好 | 声明优先级：更具体 > 更宽泛 |
| **输出与边界** | 输出什么格式、什么情况问人 | `没有就说"库中没有"，绝不编造` |

> [!tip] 排顺序有讲究
> **固定不变的内容放最前（身份→行为准则），每次会变的内容放最后（环境→项目规则）**。原因：大模型如果每次收到开头都一样，就能复用缓存，省时间省钱（这个技巧叫"前缀稳定"）。

## 第 3 步：六步写作流水线（翻译助手走一遍）

写提示词不是一次写完，是**六步循环**：

```text
拆需求 → 映射模块 → 逐块写 → 排顺序 → 加变量 → 跑起来补条款
```

用翻译助手演示：

1. **拆需求**：模型需要知道——它是翻译、翻成中文、别加戏、专有名词别乱翻。
2. **映射模块**：简单任务只要 3 块（身份 + 行为准则 + 输出格式）。
3. **逐块写**：

```text
你是中英翻译。
只输出译文，不要解释。
直接输出中文译文。
```

4. **排顺序**：固定（身份、准则）在前，`待翻译内容：{{text}}` 放最后。
5. **加变量**：`{{text}}` 每次填真内容，提示词不用改。
6. **跑起来补条款**（最关键）：真用一次，发现模型"加戏"（先回"好的，翻译结果是…"）→ **补一条**"不要任何开场白，直接给译文"；发现乱翻专有名词 → **再补一条**"品牌名、人名保留原文"。每条规矩都是一个踩过的坑。

## 第 4 步：角色怎么定（最容易纠结的点）

> [!important] 一句话原则
> **一个角色管一个"智能体"，不按"任务"重定角色。**

- 任务不同、但**共用同一套工具** → 一个角色里多写几段指引（Kimi：一个 `You are Kimi Code CLI`，下面分编码/调研/多媒体几段）
- **模式不同**（同一个人换状态）→ 加"模式切换"段，不换身份（DSH 的 plan mode 就是这样）
- 任务不同、且**工具/权限冲突**（一个要写文件、一个只许读）→ 拆成多个角色

> 判断偷懒法：**"会不会打架"比"是不是两个任务"更重要。** 既写文件又只读检索的两个活会打架 → 拆开，各给一个身份。

## 第 5 步：真实框架就是这么写的（三个例子）

| 框架 | 它的做法 | 你抄什么 |
| --- | --- | --- |
| Kimi Code CLI | 一个身份 + 7 段 `#` 指引（工具/编码/调研/环境/项目规则/技能/终极提醒） | 用 `#` 标题把模块切开，好增删 |
| DSH | plan mode 是"模式段"不是新身份；固定段在前、动态段在后 | 排顺序吃缓存 |
| Claude Code | 每条"不要 X"背后都是一个真实事故 | 跑起来，把失败补成条款 |

## 最关键的一句

> [!important]
> **提示词工程 = 搭积木：6 类模块 + 六步流水线（拆→映射→写→排→变量→补条款）。角色跟着"智能体"走，不跟着"任务"走。**

## 大白话翻译表

| 术语 | 大白话 |
| --- | --- |
| 模块 / section | 提示词里切开的一块（一段指引） |
| 身份 / persona | 大楼的招牌："你是…" |
| 变量 | 占位符 `{{cwd}}`，运行时填真值 |
| 前缀稳定 | 固定内容放最前，让模型每次开头都一样（吃缓存） |
| fail loud | 变量拼错了直接报错，不把病句发给模型 |
| 补条款 | 模型每犯一个错，就往规则里加一条对应约束 |

## 检查一下

1. 三口诀（给角色/任务/格式）对应 6 类模块里的哪几类？
2. 为什么固定内容要放最前、动态内容放最后？
3. 六步流水线的最后一步是干什么？举个真实例子。
4. "给这个助手加个'自动归类'能力"——需要新角色吗？为什么？
5. 什么情况下才该拆成两个角色？

<details>
<summary>点我看答案</summary>

1. 身份（给角色）、工具/任务（给任务）、输出与边界（给格式）——三口诀是 6 类的子集。
2. 前缀稳定：模型每次收到开头一样就能复用缓存，省时间省钱。
3. 跑起来，把失败补成新条款。例：翻译助手发现模型加戏，就补一条"不要开场白"。
4. 不需要。"自动归类"只是整理助手（同一套工具、同一个身份）里加一段指引。
5. 工具/权限冲突时（一个要写文件、一个只许读），才拆成多个角色。
</details>
