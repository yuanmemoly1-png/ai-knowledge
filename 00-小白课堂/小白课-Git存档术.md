# 小白课：Git 存档术（慢速版）

上一课：[[小白课-数据库账本]]

> [!note] 这节课学什么
> 打游戏为什么敢大胆闯关？因为有**存档**——挂了就读档重来。写代码也一样，Git 就是代码的存档机。这节课：
> - 为什么代码需要存档
> - 三件套：`init`（开存档功能）→ `add`（选要存的内容）→ `commit`（存！）
> - `log` 翻看历史存档
> - GitHub = 云端存档
>
> 所有命令都真实运行过，跟着敲一遍就会。

---

## 一句定义

**Git 是代码的存档机：每存一次就拍一张快照，改坏了随时能回到任何一次存档。**

## 第 1 步：为什么需要存档？

想象你写了一下午的代码，能跑。晚上想"优化一下"，改着改着——**崩了，而且想不起来改了哪。**

没有 Git 的人怎么自救？复制一堆 `菜单-v2-最终版-真的最终版.py`，越攒越乱。

有 Git 的人：每改好一个阶段就**存一次档**，改坏了直接回到上一个存档。仅此而已，但救命。

## 第 2 步：git init —— 给这个文件夹开存档功能

先建一个练习文件夹，进去，然后：

```bash
mkdir git-demo
cd git-demo
git init
```

输出：

```text
Initialized empty Git repository in .../git-demo/.git/
```

意思是"存档机装好了"。文件夹里多了一个隐藏的 `.git` 目录——**所有存档都藏在里面，别动它。**

## 第 3 步：git add + git commit —— 存第一个档

先写点东西进去：

```bash
echo "宫保鸡丁 38元" > menu.txt
git add menu.txt
git commit -m "第一次存档：写下菜单"
```

输出：

```text
[main (root-commit) 613b9f0] 第一次存档：写下菜单
 1 file changed, 1 insertion(+)
 create mode 100644 menu.txt
```

两个动作，分工明确：

- `git add menu.txt`：**把要存档的文件放进"存档筐"**——你可以只存某几个文件
- `git commit -m "..."`：**按快门，存！** 引号里写一句"这次存的是什么"，以后翻记录全靠这句话

> [!warning] 新手最常踩的坑
> 改了文件直接 `commit`，结果啥也没存上——**忘了 `add`**。记住顺序：先 add 放进筐，再 commit 按快门。第一次 commit 如果报 `Please tell me who you are`，按提示设置一次用户名邮箱即可（见 [[新手报错速查]]）。

## 第 4 步：再改再存 —— 存档是一串，不是一个

继续改菜单，再存一次：

```bash
echo "米饭 2元" >> menu.txt
git add menu.txt
git commit -m "第二次存档：加一道米饭"
```

## 第 5 步：git log —— 翻看历史存档

```bash
git log --oneline
```

输出：

```text
ff8f965 第二次存档：加一道米饭
613b9f0 第一次存档：写下菜单
```

**每一次存档都排在这**，最新在最上面。前面那串字母数字（`ff8f965`）是存档编号。

再查一下当前有没有"改了没存"的东西：

```bash
git status
```

输出会告诉你 `nothing to commit, working tree clean`——**干净 = 所有改动都已存档**。改坏了想回去？那句口令是 `git checkout 编号 -- 文件名`，现在先知道有这回事，用到再查 [[Git与版本控制]]。

## 第 6 步：GitHub = 云端存档

目前所有存档都在**你自己电脑**的 `.git` 里。电脑坏了怎么办？

**GitHub** 就是"云端存档库"：一条 `git push` 把本地存档传上去，换台电脑 `git pull` 拉回来。顺带的好处：别人能看到你的代码——你的 GitHub 主页就是程序员的"作品集"。

## 第 7 步：AI 写代码时代，更要勤存档

这是这节课最想说的一点。让 AI 帮你改代码时，它一次可能改 5 个文件——**改之前存一次档，改崩了一键回退，毫无心理负担。**

养成这个节奏：

```text
能跑的版本 → git add + commit → 让 AI 改 → 跑通了？→ 再存一档
                                     ↘ 崩了？→ 回到上一档，换个问法重来
```

## 最关键的一句

> [!important]
> **init 开存档、add 放进筐、commit 按快门、log 翻记录。让 AI 改代码之前，先存一档。**

## 大白话翻译表

| 术语 | 大白话 |

| Git | 代码存档机 |

## 检查一下

1. `git add` 和 `git commit` 各干什么？为什么要两步？
2. 改完文件直接 commit，会发生什么？
3. 哪条命令能看到"第二次存档：加一道米饭"这样的历史记录？
4. 为什么让 AI 改代码之前最好先 commit 一次？

<details>
<summary>点我看答案</summary>

1. `add` 把要存的文件放进存档筐（可以只选一部分），`commit` 才真正按快门存档。两步是为了让你**挑着存**。
2. 报 "nothing to commit" 之类——改动没进筐，啥也没存上。
3. `git log --oneline`。
4. 存了档，AI 改崩了可以一键回退，放心大胆地试；没存档，崩了只能凭记忆改回来。
</details>
