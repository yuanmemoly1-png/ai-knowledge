# 小白课：数据库账本（慢速版）

上一课：[[小白课-API服务员]]

> [!note] 这节课学什么
> 后厨每天记那么多账——谁点了什么、库存剩多少——到底记在哪儿？这节课回答这个问题：
> - 为什么**变量**靠不住（程序一关就没）
> - **数据库**就是后厨的账本：程序关了，账还在
> - 用 Python 自带的 `sqlite3`，亲手建一本账、记两笔、关机重开再查
>
> 每一步都有真实运行的代码和输出。

---

## 一句定义

**数据库就是程序的一本账本：数据写进去就一直在，程序关掉、电脑重启都丢不了。**

## 第 1 步：为什么变量靠不住？

你在 [[小白课-Python变量与print]] 学过变量。试试这个：

```python
kucun = {"宫保鸡丁": 2}
print(kucun)
```

输出：

```text
{'宫保鸡丁': 2}
```

很好。但**程序一结束，这个变量就没了**。下次再运行，`kucun` 又从 2 重新开始——昨天卖出去 10 份的记录，全忘了。

变量像服务员手里的**便签纸**：当下好使，下班就扔。餐厅真要记账，得用**账本**。

## 第 2 步：数据库 = 一本永远在的账本

数据库做的事一句话：**把数据写到硬盘上的文件里**，程序关了文件还在。

这节课用 `sqlite3`——**Python 自带，不用装任何东西**。它的数据库就是一个普通文件（比如 `restaurant.db`），整本账都在里面。

> 你以后听说的 MySQL、PostgreSQL 是"更大的账本"，道理一模一样，先拿 sqlite3 练手。

## 第 3 步：建账本 + 记两笔账（真的能跑）

数据库的账是一行一行记的，记之前先定好"账本有哪几列"（这一步叫**建表**）：

```python
import sqlite3

conn = sqlite3.connect("restaurant.db")   # 打开账本（没有就新建一个文件）
cur = conn.cursor()

cur.execute("CREATE TABLE orders (dish TEXT, price INTEGER)")  # 建表：两列，菜名和价格
cur.execute("INSERT INTO orders VALUES ('宫保鸡丁', 38)")       # 记第一笔
cur.execute("INSERT INTO orders VALUES ('米饭', 2)")            # 记第二笔

conn.commit()    # 关键！落笔生效
conn.close()     # 合上账本
print("账本写好了，程序结束。")
```

输出：

```text
账本写好了，程序结束。
```

逐行翻译：

- `connect(...)`：打开账本文件，没有就自动建一个
- `CREATE TABLE ...`：定账本格式——`orders` 这本账有两列：`dish`（文字）、`price`（整数）
- `INSERT INTO ...`：往账本里记一行
- `conn.commit()`：**落笔生效**。不写这行，账等于没记！
- `conn.close()`：合上账本，程序结束

## 第 4 步：程序关了，账还在吗？（见证奇迹）

**另起一个新的程序**（相当于"第二天上班"），再打开同一本账：

```python
import sqlite3

conn = sqlite3.connect("restaurant.db")
for row in conn.execute("SELECT * FROM orders"):
    print(row)
conn.close()
```

输出：

```text
('宫保鸡丁', 38)
('米饭', 2)
```

**昨天的账一笔不少。**这就是数据库和变量的全部区别。

`SELECT * FROM orders` 的意思是："把 orders 这本账**全部行**拿出来"。`for row in ...` 一行一行看——你在 [[小白课-Python条件与循环]] 学过这个循环。

## 第 5 步：三句 SQL 够你入门

刚才那三行引号里的英文叫 **SQL**——全世界数据库通用的"记账口令"。入门只需要三句：

| 口令 | 大白话 | 例子 |
| --- | --- | --- |
| `CREATE TABLE` | 新拿一本账，定好有哪几列 | `CREATE TABLE orders (dish TEXT, price INTEGER)` |
| `INSERT INTO ... VALUES` | 记一行账 | `INSERT INTO orders VALUES ('米饭', 2)` |
| `SELECT ... FROM` | 查账 | `SELECT * FROM orders` |

> [!warning] 新手最常踩的两个坑
> - **忘了 `conn.commit()`**：程序跑完一查，账是空的——没落笔。INSERT 之后必须 commit。
> - **重复运行建表那段**：第二次会报 `table orders already exists`（账本已存在）。真实项目里建表只做一次。报错对照见 [[新手报错速查]]。

## 最关键的一句

> [!important]
> **变量是便签纸（程序关就没），数据库是账本（写到硬盘永远在）。Python 自带 sqlite3：建表 → 插入 → commit → 查询。**

## 大白话翻译表

| 术语 | 大白话 |
| --- | --- |
| 数据库 Database | 后厨的账本，数据永远在 |
| 表 Table | 账本里的一页，定好有哪几列 |
| 行 row / 列 column | 一笔账 / 账的一项（菜名、价格） |
| SQL | 全世界数据库通用的记账口令 |
| `sqlite3` | Python 自带的小账本，一个文件就是一整本 |
| `commit()` | 落笔生效，不写等于没记 |

## 检查一下

1. 程序结束后，变量里的数据还在吗？数据库里的呢？
2. `INSERT` 之后忘记写哪一行，会导致"账没记上"？
3. `SELECT * FROM orders` 里的 `*` 是什么意思？
4. 第二次运行包含 `CREATE TABLE orders` 的程序，会发生什么？

<details>
<summary>点我看答案</summary>

1. 变量没了；数据库里的还在，因为它写在硬盘文件里。
2. `conn.commit()`——落笔生效那行。
3. "全部列"——把每一行的所有内容都拿出来。
4. 报错 `table orders already exists`——账本已经建过了，建表只做一次。
