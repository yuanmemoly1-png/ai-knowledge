# 小白课：Embedding 语义坐标（慢速版）

上一课：[[小白课-Prompt提示词]]

> [!note] 这节课学什么
> 这节课解决一个问题：**电脑不懂"意思"，怎么让它知道两句话像不像？**答案叫 Embedding：
> - 把每个词变成**一串数字（坐标）**
> - 意思相近的词，**坐标离得近**
> - 用"余弦相似度"**算出距离**
>
> 最后我们用纯 Python 手算一遍余弦相似度，真跑。这是下一课 RAG 的地基。

---

## 第 1 步：电脑原来只会比字面

让电脑判断"猫"和"狗"像不像，它只能比字：两个字不一样 → "不像"。但"猫"和"猫科动物"字面也很不同，它照样判"不像"——这就不行了，**字不一样不代表意思不一样**。

我们需要一种新比法：**不比字，比意思**。可电脑只认数字，所以得先把"意思"翻译成数字。

## 第 2 步：词变数字——钉在地图上的坐标

一句大白话定义：**Embedding 就是把一个词（或一句话）变成一串数字，这串数字是它在"意思地图"上的坐标**。

```
"猫"  →  [0.9, 0.8, 0.0]
"狗"  →  [0.9, 0.7, 0.0]
"汽车" →  [0.0, 0.1, 0.9]
```

这串数字有个正式名字叫**向量（vector）**。真实的模型把每个词变成**几百上千个数字**（几百上千维），我们教程里用 3 个数字演示，原理一模一样。

## 第 3 步：语义距离——离得近就是像

神奇之处在第二步的规则：**意思相近的词，坐标挨得近**。

看上面的玩具坐标："猫"和"狗"前两个数字都很大、第三个都是 0——挤在一起；"汽车"前两个接近 0、第三个很大——蹲在地图另一头。

所以"两句话像不像"这个问题，被翻译成了一个几何问题：**两个坐标离得近不近？**电脑最会算这个。

而且不只是单个词，**一整句话、一整段话也能变成一个坐标**：

```text
"今天好热"   → [0.31, 0.77, ...]
"气温真高"   → [0.29, 0.75, ...]   ← 字全不同，坐标却很近
"我想吃西瓜" → [0.88, 0.10, ...]   ← 离得远远的
```

Embedding 模型眼中，几对词的距离大概是这样：

| 这一对 | 距离 | 说明 |
| --- | --- | --- |
| "高兴" vs "开心" | 很近 | 同义词 |
| "猫" vs "狗" | 比较近 | 同类（都是宠物） |
| "猫" vs "汽车" | 很远 | 八竿子打不着 |
| "银行（存钱）" vs "银行（河岸）" | 也有点近 | 多义词是 Embedding 的老大难 |

> [!warning] 容易误会的点
> 我特意把 3 个数字标成"像动物、像宠物、像交通工具"是为了好懂。**真实模型里每个数字代表什么，人类说不清**——是模型自己学出来的维度。别试图逐个解读，只看"距离"就够了。

## 第 4 步：余弦相似度——亲手算一遍

"距离"最常用的一种算法叫**余弦相似度（cosine similarity）**：不看两个点隔多远，看两个坐标**指的方向像不像**。

- 结果接近 **1** → 方向几乎一样 → 意思很像
- 结果接近 **0** → 方向几乎无关 → 意思不像

公式别怕，就三步：对应数字相乘再相加（点积）÷ 两个向量各自的长度。翻译成 Python：

```python
import math

def 余弦相似度(a, b):
    点积 = sum(x * y for x, y in zip(a, b))
    模a = math.sqrt(sum(x * x for x in a))
    模b = math.sqrt(sum(y * y for y in b))
    return 点积 / (模a * 模b)

猫   = [0.9, 0.8, 0.0]   # [像动物, 像宠物, 像交通工具]
狗   = [0.9, 0.7, 0.0]
汽车 = [0.0, 0.1, 0.9]

print("猫 vs 狗  ：", round(余弦相似度(猫, 狗), 3))
print("猫 vs 汽车：", round(余弦相似度(猫, 汽车), 3))
```

输出：

```text
猫 vs 狗  ： 0.998
猫 vs 汽车： 0.073
```

0.998 vs 0.073——**"猫和狗很像、猫和汽车不像"这件事，电脑第一次算出来了**，而且全程没比一个字。这就是 Embedding 的全部核心。

> [!warning] 常见报错预告
> 两个向量长度必须一样。`zip` 遇到一长一短会**悄悄截断不报错**，结果就算错了——这是最难发现的一类 bug。拿真实模型的向量做计算前，先 `print(len(a), len(b))` 确认。其他报错去查 [[新手报错速查]]。

> [!note] 实际用的时候不用自己写这个函数
> 真做项目时，向量是调 Embedding API 拿到的（递一句话进去，返回几百个数字），相似度也有现成的库一行搞定。上面手算一遍，只是为了让你知道**里面没有魔法**——就是乘一乘、加一加、除一除。

## 第 5 步：这和后面的课有什么关系？

想想这个组合：**把你的资料全部变成坐标存起来 → 问题来了，把问题也变成坐标 → 找离问题最近的资料**。这就是"语义搜索"，也是下一课 RAG"查资料"那一步的发动机。

所以这一课什么都不用背，带走一句话就够：**意思可以变成数字，数字可以比距离。**

## 最关键的一句

> [!important]
> **Embedding 把词变成坐标，意思近的词坐标近；用余弦相似度算"像不像"——1 是像，0 是不像。**

## 大白话翻译表

| 术语 | 大白话 |
| --- | --- |
| Embedding 向量嵌入 | 把词/句子变成意思地图上的坐标 |
| 向量 vector | 那串数字坐标，如 `[0.9, 0.8, 0.0]` |
| 维度 | 坐标里有几个数字（真实模型几百上千个） |
| 语义距离 | 意思的差距 = 坐标的距离 |
| 余弦相似度 | 比方向像不像的算法，1 最像，0 不像 |
