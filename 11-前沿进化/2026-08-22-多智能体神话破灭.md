# 多智能体神话破灭？团队协作正在拖垮你的专家模型

> [!note] 一句话本质
> 行业都在狂堆 Agent 数量时，新论文泼了盆冷水：**多智能体团队不但没变聪明，反而在"稀释"专家的能力**——像一个全明星球队，因为人人想传球 consensus，最后打得还不如单个巨星。

## 这两篇论文说了什么

### 论文1：Multi-Agent Teams Hold Experts Back（arXiv 2602.01011）

挑战的行业共识："多智能体必然更强"。核心发现：

| 发现 | 白话解释 |
| --- | --- |
| 无法"强协同" | 多智能体团队**匹配不了团队中最强那个成员**的单独表现——1+1<1 |
| 瓶颈不是认不出专家 | 团队**知道谁最强**，但就是**用不好**他的知识 |
| **专业知识稀释效应** | 团队规模越大，性能越差——人越多，专家的声音被稀释得越厉害 |
| 唯一的好处 | 共识寻求行为提升了**对抗鲁棒性**（更难被攻击带偏）——多智能体适合安全场景，不适合性能场景 |

### 论文2：AgentArk（CMU × 亚马逊）

解决的正是上述问题：用**蒸馏**（distillation）把多智能体的推理能力**压进单个 LLM**——保留单 Agent 的高效，复刻多 Agent 的自我修正能力。翻译：与其雇一个团队开会，不如把团队的经验训练给一个员工。

## 面试价值（2026 新考点）

被问"**什么时候该用多智能体？**"的高分答案模板：

> "2026 年有论文（Multi-Agent Teams Hold Experts Back）证明多智能体团队存在'专业知识稀释效应'——规模越大性能越差，瓶颈在专家知识利用而非专家识别。所以我的默认选择是：**任务能拆干净且子任务间弱依赖**才用多智能体（如翻译+审校）；需要性能和成本时，优先单 Agent + 好工具 + 强模型——Anthropic 的复杂度递进原则和 AgentArk 的蒸馏路线都指向同一结论。多智能体的真正优势场景是对抗鲁棒性和需要不同视角验证的任务。"

原理一句话 + 论文证据 + trade-off，比背"多智能体分工协作效率高"的旧答案高一个档位。
