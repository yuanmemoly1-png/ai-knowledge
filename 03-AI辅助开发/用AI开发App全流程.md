# 用AI开发App全流程

本笔记给出一条端到端路线：从一句话想法，到上线可用的 App。全程 AI 深度参与，但每一步的「方向盘」都在你手里。建议先读 [[VibeCoding方法论]] 建立正确心态。

## 总流程图

```text
需求文档(PRD) → 技术选型 → 原型 → 前后端开发 → 测试 → 部署上线
   ↑__________________________________________________|
                  （每一步都可以回头迭代）
```

## 第一步：需求文档——让 AI 帮写 PRD

不要一上来就写代码。先用对话把想法逼成文档：

```text
> 我想做一个「待办清单」App，帮职场人管理每日任务。
  请帮我整理成一份 PRD，包括：目标用户、核心功能（按 P0/P1 优先级）、
  非功能需求、不做哪些事（明确边界）。
```

AI 会输出结构化的 PRD 草稿。你要做的是**删**：把 P0 砍到只剩 3 个功能以内。第一版越薄，上线越快。

> [!tip] 把 PRD 存进项目
> PRD 定稿后保存为项目里的 `docs/PRD.md`，并让 AI 工具的规则文件（Cursor rules / CLAUDE.md）引用它。之后每次生成代码，AI 都会自动对齐需求，不会自由发挥。

## 第二步：技术选型

让 AI 给方案，你来拍板。常见三条路线：

| 路线 | 技术组合 | 适合 | 门槛 |
| --- | --- | --- | --- |
| Web 应用 | React/Vue 前端 + Flask/FastAPI 后端 | 通用工具、想用浏览器打开就用 | 中 |
| 微信小程序 | WXML/WXSS/JS + 云开发 | 面向国内用户、社交传播 | 低（免后端运维） |
| 桌面/本地工具 | Python + Tkinter/PySide，或 Electron | 个人工具、数据处理 | 低 |

> [!note] 新手选型建议
> 第一次做产品，优先选微信小程序（云开发免服务器）或纯前端 Web 应用（无后端可维护性负担）。把「做出能用的东西」排在「技术先进」前面。小程序方向详见 [[微信小程序开发入门]]。

## 第三步：原型

两种快法：

1. **文字原型**：让 AI 把每个页面的布局用文字/ASCII 画出来，确认信息结构。
2. **可点原型**：让 AI 直接生成一个纯前端的静态页面（HTML 或小程序页面），数据写死，先看「长什么样、点起来顺不顺」。

原型阶段改一次的成本是几分钟，开发完再改就是几小时——尽量在原型期把交互定死。

## 第四步：前后端开发

进入主开发阶段，纪律照 [[VibeCoding方法论]]：小步迭代、每步 commit、顺手写测试。推荐的开发顺序：

1. **数据先行**：让 AI 设计数据库表/数据结构，你确认。数据结构定了，其他都是围绕它的增删改查。
2. **后端接口**：一次一个接口。「实现 POST /api/todos 创建待办，参数校验、错误码齐全，附测试」。
3. **前端页面**：一次一个页面，接真接口前先用假数据把页面跑通。
4. **联调**：前后端接上，把报错一条条喂给 AI 修。

> [!warning] 安全红线不外包
> 密码哈希、登录态校验、越权检查、SQL 注入防护——这些 AI 会写，但也可能写漏。涉及安全的代码逐行审查，密钥一律走环境变量。

## 第五步：测试

- 让 AI 为每个接口/函数补单元测试（pytest、Jest 等）。
- 让 AI 扮演用户跑一遍核心流程：「列出这个 App 所有可能出错的用户操作」，把清单变成手工测试用例。
- 找 2-3 个真实用户试用，他们的反馈比任何测试都值钱。

## 第六步：部署

按路线选择：

- **Web 前端**：Vercel、Netlify——关联 GitHub 仓库后推送即自动部署，免费额度够个人项目用。
- **Web 后端**：Railway、Render 等 PaaS，或云服务器 + Docker（让 AI 生成 Dockerfile）。
- **微信小程序**：微信开发者工具上传 → 提交审核 → 发布（详见 [[微信小程序开发入门]]）。

部署配置文件都可以让 AI 生成，但**账号、密钥、域名**这些资产握在自己手里。

## 附：最小项目示例规划——待办清单 App

一个可以在 1-2 天内走完全流程的练手项目：

| 阶段 | 任务 | 给 AI 的关键指令 |
| --- | --- | --- |
| PRD | P0：增删待办、标记完成；P1：截止日期 | 「把待办清单想法整理成 PRD，P0 不超过 3 个功能」 |
| 选型 | 微信小程序 + 云开发（免服务器） | 「对比 Web 和小程序方案，我是零基础」 |
| 原型 | 单页面：顶部输入框 + 下方任务列表 | 「生成静态原型，数据写死 5 条假任务」 |
| 开发 | 云函数 3 个：addTodo / listTodos / toggleTodo | 「实现 listTodos 云函数，按创建时间倒序」 |
| 测试 | 手测 10 条用例（空输入、超长文本等） | 「列出这个 App 的边界测试用例清单」 |
| 部署 | 开发者工具上传 → 提交审核 | 「小程序提交审核前要检查哪些项」 |

走完这一圈，你就拥有了「想法 → 上线」的完整肌肉记忆，之后做更大的项目只是复制这套节奏。
