# 微信小程序开发入门

微信小程序是国内个人开发者触达用户成本最低的渠道之一：不用下载安装、微信内即点即用，配合「云开发」还能免掉服务器运维。而小程序页面结构高度模板化，恰好是 AI 辅助生成效果最好的场景之一。

## 技术栈：四件套

一个小程序页面由四个同名文件组成，各管一件事：

| 文件 | 类比 | 职责 |
| --- | --- | --- |
| `.wxml` | HTML | 页面结构：有哪些元素、怎么排 |
| `.wxss` | CSS | 页面样式：颜色、字号、间距 |
| `.js` | JavaScript | 页面逻辑：数据、事件处理、网络请求 |
| `.json` | 配置文件 | 页面配置：标题、导航栏颜色等 |

全局还有一组 `app.wxml`（无，实际为 `app.js` / `app.json` / `app.wxss`）：`app.json` 注册所有页面，`app.js` 放全局逻辑，`app.wxss` 放公共样式。

一个最小页面长这样：

```html
<!-- pages/index/index.wxml -->
<view class="container">
  <input placeholder="输入待办" bindinput="onInput" value="{{inputValue}}" />
  <button bindtap="addTodo">添加</button>
  <view wx:for="{{todos}}" wx:key="index" class="todo-item">
    <text>{{item.text}}</text>
  </view>
</view>
```

```javascript
// pages/index/index.js
Page({
  data: {
    inputValue: "",
    todos: [],  // data 里的数据通过 setData 修改后会自动刷新视图
  },
  onInput(e) {
    this.setData({ inputValue: e.detail.value });
  },
  addTodo() {
    if (!this.data.inputValue.trim()) return;
    this.setData({
      todos: [...this.data.todos, { text: this.data.inputValue }],
      inputValue: "",
    });
  },
});
```

> [!note] 与 Web 前端的三个关键差异
> - 标签不是 `div` 而是 `view`，`span` 换成 `text`，`img` 换成 `image`。
> - 数据绑定用 `{{双大括号}}`，改数据必须调 `this.setData()`，直接赋值不会刷新页面。
> - 事件绑定是 `bindtap`（点击）、`bindinput`（输入）这类属性，不是 `onclick`。

## 微信开发者工具

官方 IDE，开发小程序的唯一入口，免费下载：

1. 到微信公众平台下载「微信开发者工具」（稳定版即可），用微信扫码登录。
2. 注册小程序账号：个人主体免费注册，拿到 **AppID**（测试阶段也可以用测试号）。
3. 新建项目 → 选「小程序」→ 填 AppID → 模板选「不使用云服务」或「云开发」。

工具的核心区域：

- **模拟器**：实时预览页面，可切换不同手机型号。
- **编辑器**：写四件套代码（也可以用 Cursor 写代码、开发者工具只做预览和上传）。
- **调试器**：Console 日志、网络请求、Storage 数据都在这里看。
- **上传按钮**：把代码提交到微信后台，是发布流程的第一步。

## 用 AI 辅助生成页面和云函数

小程序代码模板化程度高，AI 生成质量普遍不错，关键在提示词要给足约束。

### 生成页面

```text
> 写一个微信小程序「待办列表」页面的四件套（wxml/wxss/js/json）：
  - 顶部输入框 + 添加按钮，下方任务列表
  - 每条任务左侧圆形勾选框，点击切换完成状态，完成的文字加删除线
  - 左滑出现删除按钮（或用长按删除）
  - 数据先存本地 wx.setStorageSync，不接后端
  样式风格：简洁、主色 #4F8CFF、圆角卡片
```

生成后逐项验收：四件套是否齐全、`bind` 事件和 js 里的函数名是否对得上、`setData` 用法是否正确。AI 偶尔会把 Web 的写法（`div`、`onclick`）混进来，这类错误一眼就能在模拟器里发现。

### 生成云函数（云开发）

云开发让你在微信的云环境里直接写后端，无需买服务器。一个云函数就是一个 Node.js 函数：

```javascript
// cloudfunctions/addTodo/index.js
const cloud = require("wx-server-sdk");
cloud.init({ env: cloud.DYNAMIC_CURRENT_ENV });
const db = cloud.database();

exports.main = async (event) => {
  // event 里是小程序端 wx.cloud.callFunction 传来的参数
  const { text } = event;
  if (!text || !text.trim()) {
    return { code: 400, msg: "内容不能为空" };
  }
  const res = await db.collection("todos").add({
    data: { text: text.trim(), done: false, createdAt: db.serverDate() },
  });
  return { code: 0, data: { _id: res._id } };
};
```

小程序端调用：

```javascript
const res = await wx.cloud.callFunction({
  name: "addTodo",
  data: { text: this.data.inputValue },
});
```

> [!tip] 让 AI 写云函数时的三条约束
> 1. 明确说「微信云开发 + wx-server-sdk」，否则它可能写成 Express 等普通 Node 后端。
> 2. 要求「参数校验和错误码齐全」，云函数是公网入口，不做校验等于开门揖盗。
> 3. 数据表结构先说清楚（表名、字段），AI 生成的增删改查才能对上。

> [!warning] 数据库权限
> 云开发控制台里每张表有权限设置（如「仅创建者可读写」）。AI 生成的代码默认假设你能读写，联调报错时先检查控制台权限，这是新手最常见的坑。

## 发布与审核流程概述

```text
开发者工具「上传」→ 微信公众平台设为「体验版」自测
→ 提交审核 → 审核通过 → 手动点「发布」→ 全网上线
```

要点：

- **体验版**：上传后先在后台设为体验版，自己和白名单成员扫码真机测试。
- **类目选择**：提交审核时要选服务类目，个人主体可选类目有限，做之前先确认你的品类个人能不能做。
- **审核时长**：通常几小时到几天，涉及内容、支付、医疗等敏感类目更严。
- **常见驳回原因**：功能与类目不符、页面有未实现的死按钮、收集用户信息但无隐私协议。现在小程序必须配置《用户隐私保护指引》，在公众平台后台填写。
- **迭代发布**：之后每次更新走同样流程，老用户会自动收到新版本。
