### 2.5 Linux 与命令行
- 为什么学：部署、连服务器、看日志、排查进程全靠它；不会命令行的人「部署」无从谈起
- 命令按**场景**组织而不是背清单：目录与文件（cd/ls/pwd/mkdir/rm -rf 的危险）、看文件（cat/less/head/tail -f）、找东西（find/grep）、权限（chmod/sudo）、进程（ps/top/kill）、网络（curl/ssh/ping）、**管道与重定向（| > >>）**
- 管道组合是 Unix 哲学的核心：小工具各干一件事，串起来解决大问题——给一个真实例子
- 动手看：`grep ERROR app.log | awk '{print $4}' | sort | uniq -c | sort -rn | head` 这类「统计日志里最多的错误」组合命令，逐段解释
- 不该用：不背全部参数，用到再查；明确警告 `rm -rf` 的危险

### 2.6 测试与质量保障
- 为什么学：AI 生成的代码**看起来对 ≠ 跑起来对**；没有测试，改一处坏一处，越改越怕
- pytest 最小用法：断言、运行命令、fixture；给 FastAPI 接口写测试（httpx）
- **测 LLM 应用和普通软件的区别**（本节核心）：输出不确定 → 断言「结构」而不是「精确内容」；测关键词命中、JSON 结构、长度范围，而不是逐字相等
- 不该用：原型期别追求覆盖率；对不确定输出别用精确相等断言

### 3.9 Docker 与容器化
- 为什么学：「在我机器上是好的」——容器一次构建到处运行；也让别人能一键复现你的作品
- 镜像 vs 容器的类比（镜像=压缩好的模板/菜谱，容器=跑起来的实例）；Dockerfile 最小示例（Python + FastAPI：FROM / WORKDIR / COPY / RUN / CMD）
- 常用命令：build / run（含 -p 端口映射）/ ps / logs / exec；镜像分层与缓存（为什么 COPY 依赖放前面）
- 不该用：本地跑个脚本不需要容器；学习阶段别一上来就 K8s，先 `docker run` 玩明白

### 5.5 推理服务与部署优化
- 开头给**分界判断**：什么时候自己扛模型（流量大 / 数据不能出域 / 深度定制），什么时候直接调 API（大多数应用岗）
- vLLP 类推理框架解决什么：continuous batching（吞吐）、PagedAttention（显存）、为什么「批处理」是吞吐的核心手段
- KV Cache 为什么是推理的关键（它是什么、为什么省了重复计算、为什么吃显存）
- 量化：INT8 / INT4 / FP8 的取舍（精度损失 vs 显存减半 vs 速度）
- 时延 vs 吞吐是两条不同的优化线（先问清楚你优化哪个）
- 不该用：流量小直接调 API 更省；别为了简历硬上自部署
- 注意：5.5 的三个 `qs`（in-01 KV Cache / in-02 量化 / in-03 时延优化）考点必须真正覆盖

### 5.6 成本测算与降本
- 先算清账：成本 = 输入 token + 输出 token（输出更贵）+（自部署时的显存与机器）；**多轮对话的历史滚雪球**是最大隐形杀手
- 降本四板斧，按优先级：① 砍历史上下文（压缩/裁剪/只带相关轮）② 缓存（前缀缓存、语义缓存及适用条件）③ 路由到小模型（简单请求用便宜模型）④ 批处理
- 核心立场：**每次降本都必须拿评测护航**——没有评测的降本是暗降，今天省的钱是明天赔的用户
- 动手看：给一个「算一次 Agent 多轮任务的 token 账」的小脚本
- 不该用：别在没评测的情况下换模型

### 22.4 从 GUI 到真实世界（Computer Use）
- **先读原书附录 B**（直链见下），再写；内容忠于原文，用自己的话
- 模式是什么：Agent 通过**截屏观察 + 模拟鼠标键盘**操作真实界面，而不是调 API——GUI 是「最后的通用接口」，因为大量系统没有 API
- 机制循环：截屏 → 视觉理解 → 定位坐标 → 模拟操作 → **再截屏验证** → 循环；验证这一步是关键
- 与工具调用/MCP 的对比：API 快而稳但要求对方开放；GUI 慢、贵、脆弱但**通用**
- 风险与护栏：误操作、无限循环、必须设步数上限与人在回路
- 动手看：最小循环伪代码
- 不该用：有 API 就别走 GUI；长流程易碎场景慎用
