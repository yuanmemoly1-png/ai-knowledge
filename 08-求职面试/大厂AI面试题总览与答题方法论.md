# 大厂 AI 面试题总览与答题方法论

> [!note] 这篇笔记的定位
> [[AI面试八股文]] 回答"**考什么**"，本笔记回答"**怎么答最好**"。内容基于 2025-2026 牛客、CSDN、掘金、代码随想录、腾讯云社区等渠道的字节/阿里/腾讯/小米/美团/快手/百度/蚂蚁真实面经整理。

| --- | --- | --- |

## 二、高频题清单（按模块）

> 完整概念解析走 [[AI面试八股文]] 的双链，此处只列题目 + 答题要点。

**A. Transformer 原理（算法岗地基）**
1. Transformer 结构 / LayerNorm 对哪个维度归一化 / pre-norm vs post-norm（现在主流是 pre-norm）
2. 为什么除以 √d_k —— 方差推导：Q·K 点积方差随维度线性增长，不除会把 softmax 压进梯度饱和区
3. 位置编码演进：正弦绝对 → 可学习 → **RoPE**（Llama/Qwen 主流）/ ALiBi，为什么 RoPE 利于长文本外推
4. BERT(MLM/NSP) vs GPT(AR) vs T5；为什么主流 LLM 都选 **Decoder-only**（训练效率、生成能力、scaling 友好）
5. MoE 原理与代价（稀疏激活、路由不稳定、通信开销）；涌现能力

**B. 训练与微调**
6. 预训练 → SFT → RLHF/DPO 全流程；PPO vs DPO（DPO 无需奖励模型、更稳不易训飞）
7. LoRA：为什么有效（ΔW 低秩假设，Intrinsic Dimensionality 研究）、rank 怎么选、**学习率为何比全参微调大 1-2 个数量级**（冻结主干、小参数量需要更快收敛）、merge 与不 merge 的取舍
8. 7B 全参微调显存手算：权重 bf16(14G) + 优化器状态 fp32 Adam(56G) + 梯度 + 激活 ≈ 60G+，所以用 LoRA
9. 微调 vs RAG vs Prompt 怎么选（几乎每场面试的开场白，见方法论第 3 条）

**C. RAG（2026 每场面试标配）**
10. RAG vs 微调的本质：**RAG 是开卷考试，微调是把知识背进脑子**；生产惯例 RAG-First
11. 完整流水线：离线（解析→切分→Embedding→入库）+ 在线（query 改写→混合检索→重排→生成→引用溯源）
12. chunk 策略：语义边界切分 + 保留标题层级 + 10-20% overlap；父子文档切片（子片段检索、父片段注入）——面经真实数据 53%→93%
13. BM25 vs 向量检索优劣与混合方案（RRF 融合）：BM25 抓专有名词精确匹配，向量抓语义口语化
14. **RAG 准确率 60%→85% 怎么做**（区分度最高的题，见方法论第 2 条四环节拆法）
15. 多轮指代消解：query 改写把"这个条款"补全成独立问题，但要加语义校验防改歪（相似度过低回退原 query）

**D. Agent（大厂 AI 岗第一高频）**
16. Agent / Workflow / Chatbot 区别（腾讯必问）
17. ReAct 循环细节；Function Calling vs MCP vs A2A
18. 记忆系统设计（短期滑动窗口/摘要压缩，长期向量库/文件）
19. **工具调用死循环怎么办**（字节高频）：最大迭代数 10-20 + 循环检测 + 超时重试 + 降级兜底
20. Multi-Agent 协作架构（Supervisor-Worker / 流水线 / 群聊辩论）
21. **Agent 架构有哪几种格式、分别的例子** → 本文第三节专项

**E. 推理与部署**
22. KV Cache 原理 → PagedAttention/vLLM（吞吐 3-5 倍）；为什么标称上下文用到 60-70% 就开始降（lost-in-the-middle + 位置外推不稳）
23. INT8/INT4/FP8 差异要报得出数字：INT8 显存 -75%、精度损失 1-2%；INT4 -87.5%、损失 10-15%；FP8 浮点格式 E4M3/E5M2、损失比 INT8 低
24. 推理时延优化全家桶：continuous batching + 量化 + 投机解码 + 蒸馏
25. 流式输出实现（SSE/WebSocket）+ 断线恢复上下文（stream_id 持久化 + 增量缓存 + 断点续传）

**F. 场景设计题（拉开档位的关键）**
26. **设计一个智能客服，核心难点在哪**（各厂都考）
27. 设计文档问答系统 / AI 代码助手 / 搜索排序（混合检索）
28. 模型输出不稳定 / 幻觉怎么治理（RAG + 引用校验 + 结构化验证 + 拒答策略）

**G. AI 产品经理**
29. 大模型能力边界：强项（生成/推理/代码）弱项（数学/实时信息/多模态）+ 产品侧怎么补（RAG/Agent/SFT）
30. RAG 和 Agent 的区别一句话：**"RAG 让 AI 记得更准，Agent 让 AI 干活更稳"**
31. 落地案例必用 STAR + 量化数据；评估分阶段：验证期（准确率/完成率）→ 成长期（DAU/NPS）→ 成熟期（ROI/降本额）

## 三、Agent 架构格式与代表例子（面试专项）

腾讯必问"Workflow 和 Agent 的区别"、阿里要求现场画三层架构——这一节就是这类题的答题模板。

### 3.1 先分两大类（Anthropic《Building Effective Agents》的分法）

| | Workflow 工作流 | Agent 智能体 |
| --- | --- | --- |
| 控制流 | **代码写死的图**，LLM 只在节点里干活 | **LLM 自己决定**下一步做什么 |
| 可预测性 | 高，路径确定 | 低，但能应对未知路径 |
| 适合 | 步骤固定的业务（审批、客服流程） | 开放性任务（调研、写代码） |
| 例子 | Dify 工作流、n8n | Claude Code、Manus |

### 3.2 七种架构格式速查表

| # | 格式 | 一句话原理 | 代表例子 |
| --- | --- | --- | --- |
| 1 | **Workflow 确定性工作流** | 固定状态图编排，LLM 填节点 | LangGraph 状态图、Dify/扣子工作流、n8n |
| 2 | **Router 路由分发** | 先分类再走不同固定链路 | 智能客服意图分流（FAQ→RAG→Agent→人工）；简单 query 走小模型、复杂走大模型的模型路由 |
| 3 | **ReAct 单 Agent 循环** | Thought→Action→Observation 交替直到完成 | Claude Code、Cline/Cursor Agent 模式、LangChain ReAct Agent、ChatGPT 工具调用 |
| 4 | **Plan-and-Execute** | 先全局规划步骤列表，再逐步执行，必要时重规划 | BabyAGI、HuggingGPT（LLM 当调度器调模型库）、LangGraph Plan-and-Execute 模板、Manus |
| 5 | **Reflection 反思迭代** | 生成→自我批判→修正，循环到达标 | Reflexion、Self-Refine；代码 Agent"跑测试→读报错→修复"循环 |
| 6 | **层级式 Multi-Agent**（Supervisor-Worker） | 主管 Agent 派活、汇总，员工各管一摊 | LangGraph Supervisor、CrewAI Hierarchical 模式、MetaGPT（软件公司：PM→架构师→工程师→QA） |
| 7 | **协作式 Multi-Agent**（群聊/流水线/辩论） | 多个专职 Agent 平等对话或按序传递 | AutoGen GroupChat、ChatDev、CrewAI Crew（研究员→写手→审校流水线） |

> [!tip] 加分延伸
> 提一嘴 **ReWOO**（Reasoning Without Observation）：把规划一次性做完再执行，不在每步携带全部观察，比标准 ReAct 省 Token——字节问 ReAct 细节时说出来很加分。模式原理详解见 [[ReAct与Agent设计模式]]，四要素（规划/记忆/工具/行动）见 [[Agent核心架构]]。

### 3.3 答题模板：被要求"设计一个 Agent 系统"时

阿里要求画的**三层架构**可以直接套：

```text
路由层（Router）：意图分类，简单问题走 FAQ/小模型，复杂问题升级
    │
管理/规划层（Supervisor）：任务拆解、分派给执行 Agent、汇总结果、异常兜底
    │
执行层（Worker）：RAG 检索、工具调用、代码执行、API 操作……各 Agent 单一职责
```

回答顺序：**先反问需求边界**（用户是谁/解决什么/资源多少）→ **给分层架构** → **主动讲难点**（多轮失忆→显式抽取关键实体；指代消解→query 改写；情绪/风险→转人工兜底）→ **生产护栏**（迭代上限、结构化输出、human-in-the-loop）。

### 3.4 复杂度递进原则（必说的收尾）

Anthropic 的原则：**能用单次 LLM 调用解决的就不要上 Workflow，能用 Workflow 解决的就不要上自主 Agent**。每加一层自主性就多一份 Token 开销和失败点。先跑通最简单方案，复杂度只在必要时引入。

## 四、答题方法论：怎么答才是"最好"

通读面经里面试官的点评和追问链，好答案的规律高度一致，提炼 6 条：

### 1. 考察逻辑已从"知道"变成"做过"

代码随想录原话："你得真做过项目、真踩过坑，面试官一追问细节就露馅。"好答案结构永远是：**原理一句话 → 我项目里遇到过 → 我怎么解决的 → 数据变化多少**。

对比"为什么除以 √d_k"：差答案背"防止 softmax 饱和"；好答案是讲完方差推导补一句"我手写 attention 时不除它，长序列 loss 会抖"——同一句话，后者证明你写过。

### 2. 分层框架 + 具体数字，是万能高分模板

以"RAG 准确率 60%→85%"为例，按四环节拆，而不是说"换 embedding 模型/调大 top-k"：

| 环节 | 动作 |
| --- | --- |
| 离线数据 | 语义边界切分 + 保留标题层级 + 10-20% overlap + 父子文档 |
| 在线查询 | query 改写 + 语义校验（相似度 <0.8 回退原 query，防改歪） |
| 检索生成 | BM25+向量双路 → RRF 融合 → Cross-Encoder 重排 → 动态 TopK |
| 评估闭环 | 建 golden set，每次改动跑回归，不靠感觉 |

每个环节带上自己项目的数字，可信度立刻不同。

### 3. 讲 Trade-off，不讲银弹

资深面试官在验证判断力。所有选型题都用"**维度对比 + 场景结论 + 结合方式**"作答。例如微调 vs RAG：知识更新→RAG，行为/风格→微调；生产惯例 **RAG-First**；进阶答法是互补——微调教模型"如何利用检索结果"，RAG 提供事实。

### 4. 场景题先反问，再分层设计，最后主动讲难点

主动讲出"多轮失忆、指代消解、情绪检测"三大难点的人，和只会画架构图的人，档位立分。牛客高赞的智能客服题解法：意图分类拦异常 → FAQ 直答 → RAG 知识库（温度 0.1）→ 多轮任务走 Agent 状态机+每步确认 → **转人工兜底**（带对话摘要过去，人工不用重复问）。

### 5. 生产化视角是高级岗位的分水岭

初级讲"怎么实现"，高级讲"**怎么不出事**"：约束动作空间、强制 JSON schema、最大迭代 10-20 + 超时重试、高风险操作 human-in-the-loop、监控告警 + 降级。场景题没有兜底方案（拒答/转人工/降级）是面经里被点名的硬伤。

### 6. 主动埋钩子，把追问引向主场

小米/字节是打断式追问链（Transformer → 输入维度 → LayerNorm 哪个维度 → 为什么），无法预测走向，但可以每层回答留一个你熟的延伸点（讲 KV Cache 时顺带说"我们当时用 PagedAttention 解决显存碎片"），把面试变成主场。

## 五、面经点名的雷区

- ❌ 量化题只说"位数少省显存"，说不出精度损失范围和 FP8 vs INT8 差异
- ❌ 说得出 RAG 流程，说不出自己用的 embedding 模型结构和输出维度
- ❌ 场景题无兜底；评估题只报单一指标
- ❌ 被追问"为什么"时只会重复定义
- ❌ 多智能体当银弹：不提成本和失败点，直接上 Multi-Agent 架构
