# Agent 自进化：从"会做事"到"会成长"

> [!note] 一句话理解
> 今天的 Agent（Cursor、豆包…）本质是**一次性对话工程**——任务结束后不会成长。自进化要解决的核心问题：**真实任务里的经验，怎么变成下一次任务可复用、可验证、可治理的能力**。

> [!info] 来源说明
> 本文基于抖音 @清华姜学长 的视频主题，结合清华大学 AIR 刘洋教授团队的可进化智能体研究、Princeton/Tsinghua/CMU 联合综述《A Survey of Self-Evolving Agents》、奇点逃逸 Nexus 实践、Karpathy autoresearch 项目等多方来源整理。

## 一、为什么 Agent 需要自进化？

### 当前的痛点：聪明但失忆

| 问题 | 表现 | 例子 |
| --- | --- | --- |
| 无持久记忆 | 每次对话从零开始 | 今天纠正过的错误，明天换个会话又犯 |
| 经验无法沉淀 | 成功路径不复用 | 解决过的同类问题，每次都完整推理一遍 |
| 重复试错 | Token 和时间浪费 | 同一个工具调用报错，每次都踩同一个坑 |
| 无法适应用户 | 不学偏好 | 用户喜欢简洁回答，Agent 每次都长篇大论 |

> [!tip] 一个生动的类比
> 没有"自进化"的 Agent，就像一个**每天早上醒来都忘记昨天的聪明工程师**——他可能很强，但永远无法积累专业技能。加了记忆的 Agent 能记住事实，但只有自进化 Agent 能把经验**提炼成可复用的技能**。

### 根本原因：LLM 是静态的

> [!quote] 20 校联合综述开篇引用达尔文
> "存活下来的不是最聪明或最强壮的物种，而是**最能适应变化环境**的物种。"
> —— "最强壮" = 参数最多、数据最多的巨无霸模型；"最聪明" = Benchmark 得分最高的模型。但它们本质是**静态的**（static）。AI 正被部署到开放、多变、不确定的真实世界，仅"强壮"或"聪明"不够——**适应性才是通往 AGI/ASI 的关键路径**。

大模型一旦训练完成，参数就固定了。它无法自己适应：
- **全新任务类型**（novel tasks）
- **知识领域持续演化**（新框架、新 API）
- **动态交互上下文**（用户需求变化、环境变化）

自进化的范式转变：从 **"缩放静态模型"**（scaling static models）→ **"开发自进化 Agent"**（self-evolving agents）。

### 开环 vs 闭环：一眼看懂差别

```text
常规 Agent（开环）：任务输入 → 规划 → 工具调用 → 执行 → 结果 ✂ 经验蒸发
自进化 Agent（闭环）：结果 → 反馈 → 反思 → 沉淀经验 → 更新能力 → 下次更强 ↺
```

**反思（Reflection）是闭环的核心枢纽**：对成功/失败案例归因——是规划缺陷？工具误用？参数错误？——形成可复用方案并持久化。注意：Agent 不能直接改自己的模型权重，所以自进化必然**分层进行**（见下节四层）。

## 二、自进化的四个层面

> 参考腾讯云社区、掘金多篇文章的工程化分层，从易到难排序：

### 层面 1：上下文进化（最容易落地）

**进化什么**：把执行经验、用户偏好、环境约束写回本地记忆文件、会话索引或技能目录，下次任务触发时通过检索拼接入上下文。

**例子**：
- Claude Code 的 `CODELY.md` / `AGENTS.md` 文件——每次会话自动加载，项目规范不需要重复说
- Hermes Agent 的 `MEMORY.md`（2200字）+ `USER.md`（1375字）——Agent 自己写、自己读
- 踩过的坑（"这个 API 需要先鉴权"）写进记忆，下次自动避开

**本质**：文本资产的积累和检索，改动的是 **Agent 看到的上下文**。→ 详见 [[记忆与上下文工程]]

### 层面 2：技能进化（工程价值最高）

**进化什么**：把成功经验外化成结构化的 **Skill 包**（如 `SKILL.md`、技能脚本、工作流模板）。系统依据执行反馈自动修改技能代码，在测试集中跑通后覆盖老版本，失败则版本回滚。

**例子**：
- Agent 第一次处理"解析 PDF 表格"花了很多步骤试错；成功后把流程固化成一个 Skill，下次直接调用
- Karpathy 的 `autoresearch` 项目：Agent 做完一轮文献调研后，把有效的搜索策略沉淀成可复用的工作流
- Codely CLI 的 Skills 系统：每个 Skill 是一个 `SKILL.md`，包含指令、资源引用和触发条件

**关键设计**：
```text
执行任务 → 收集反馈（成功/失败/报错）
    │
    ▼
提炼经验 → 生成或修改 Skill
    │
    ▼
独立评测 → 在测试集验证 → 通过则采用，不通过则回滚
```

> [!warning] 技能进化的前提
> 不是赋予 Agent 无限自主权，而是建立**证据和治理边界**。系统必须能回答：为什么要改？改了什么？是否真的更好？有没有损害原有能力？出问题时能否撤回？

### 层面 3：群体智能进化

**进化什么**：多个 Agent、多台机器、多个用户的本地经验接入云端共享层。服务端完成轨迹去重、冲突合并、安全脱敏与质量验证，最后将提纯后的技能或记忆分发回所有终端。

**例子**：
- 用户 A 的 Agent 学会了"处理某银行 API 的特殊鉴权"，脱敏后分发到所有用户的 Agent
- MetaGPT 的多智能体软件公司：PM→架构师→工程师→QA，协作过程中各自积累经验
- 奇点逃逸 Nexus：人、Agent、任务、知识和工具基于同一份组织状态持续协作，系统从每次协作中有证据地变强

**额外挑战**：数据脱敏、权限控制、冲突合并、质量验证——比前两层复杂得多。

### 层面 4：策略进化（终极形态）

**进化什么**：将真实交互轨迹与成败反馈收集起来，直接修改 Agent 的核心调度代码、工作流拓扑，甚至转化为强化学习（RL）的奖励信号来更新大模型参数。

**例子**：
- SEED（清华等机构）：让 Agent "事后复盘"自己的轨迹，把"事后技能"作为训练信号，用 on-policy 蒸馏内化进模型参数——推理时"私教"消失，经验已吃进权重
- CUDA Agent（清华 AIR × 字节）：用大规模 Agent 强化学习训练模型生成高性能 CUDA 代码，从试错中持续进化

**落地难度**：需要 GPU 资源、标注数据、训练管线，目前只有大厂和研究机构能做。

### 四层对比

| 层面 | 进化对象 | 落地难度 | 谁能做 | 回滚成本 |
| --- | --- | --- | --- | --- |
| 上下文进化 | 记忆文件、提示词 | ★☆☆☆☆ | 个人开发者 | 低（改文本） |
| 技能进化 | SKILL.md、工作流脚本 | ★★☆☆☆ | 小团队 | 低（版本控制） |
| 群体智能进化 | 云端共享技能/记忆 | ★★★★☆ | 平台型产品 | 中（需治理） |
| 策略进化 | 模型参数、调度代码 | ★★★★★ | 大厂/研究机构 | 高（需重训） |

> [!tip] 工程建议
> **上下文闭环和技能闭环是最佳起始点**——改动的是文本资产，容易审计、故障可控、回滚成本低。先跑通这两层，再考虑群体和策略进化。

## 三、学术框架：五个问题与一个验证门槛

Princeton/Tsinghua/CMU 联合综述《A Survey of Self-Evolving Agents》把自进化拆成 What/When/How/Where 四个维度；腾讯云《Agent 自进化系列》补充了第五问 Who，以及一条硬性验证门槛：

| 维度 | 问题 | 回答 |
| --- | --- | --- |
| **What** | 进化什么对象？ | 记忆（经验笔记）、工具（新技能包）、工作流（流程优化）、模型参数（策略本身） |
| **When** | 什么时候进化？ | 任务内（每次 Action 后即时调整）、任务间（完成后复盘）、跨任务（历史经验迁移） |
| **How** | 怎么进化？ | 四种更新算子：上下文更新（反馈提炼为规则注入 Context）、监督更新（成功轨迹用于训练）、奖励驱动更新（环境反馈转 RL 奖励）、模仿学习（学习自身/他人高质量示范） |
| **Where** | 进化发生在哪里？ | 模型内部（参数微调）、模型外部（Harness 层：记忆/工具/Prompt）、混合（两者结合） |
| **Who** | **谁在进化谁？** | 见下表——这决定了自进化的可信度和安全边界 |

### Who：Solver 与 Evolver 的五种关系

| 模式 | 谁进化谁 | 特点 |
| --- | --- | --- |
| Self-reflection | 同一 Agent 自己反思自己 | 实现简单，但容易**自我确认、错误归因** |
| Self-harness | 同一模型分饰两角（求解循环 vs 进化循环分开） | 模型相同、职责分离 |
| Meta-evolution | 独立的 Evolver 修改 Solver | 可跨任务分析轨迹，专门优化 Harness |
| Population evolution | 多个 Solver/Evolver 竞争组合 | 候选群体 + 评分 + 选择，类进化算法 |
| Human-in-the-loop | 人决定怎么更新，Agent 执行 | 安全可控，但还不是完全自主进化 |

> [!warning] 验证门槛（没有它就不叫自进化）
> 同一个"单元测试通过"的结果，可以被写成一条 Memory，也可以用来筛选 Prompt 或触发 RL 训练——**关键区别不在存了什么，而在有没有验证**。规范做法：Evolver 提出有界的修改 → **回归测试通过才晋升**，失败则回滚。没有这道门槛，经验库只会越攒越乱、错误经验也会被沉淀。

### 关键洞察：从"记忆"到"技能"的范式升级

记忆不应只是被动检索的"日记本"，而应被组织成 **可执行、可验证、可进化的"技能"**：

```text
普通 Agent Memory：         自进化 Agent Memory：
  History                     History
    ↓                           ↓
  Store                        Distill Experience（提炼经验）
    ↓                           ↓
  Retrieve                     Guide Capability Creation（指导创建新能力）
    ↓                           ↓
  Answer                       Create Executable Asset（创建可执行资产）
                                ↓
                              Validate → Persist → Use（验证→持久化→使用）
                                ↓
                              Generate New Experience（产生新经验→循环）
```

**分界线**：普通 Agent 的 Memory 只是给 LLM 增加上下文；自进化 Agent 的 Memory 开始**修改 Agent 自身的结构**（新增工具、改写工作流、更新技能包）。

## 三点五、零训练的即时进化：Self-Refine 与 Reflexion

> [!info] 2026-08-22 补充（抖音@喜欢哩 图文主题引出）
> 自进化不一定要重训参数——有一族**纯推理期**的自我改进方法，只靠提示词让模型"自己改自己的作业"，是四层模型里最轻量的"任务内进化"。

| 方法 | 核心循环 | 一句话 |
| --- | --- | --- |
| **Self-Refine**（2023） | 生成 → 自我批评（同一模型换"挑剔编辑"角色）→ 修订，循环 k 次 | 模型**识别错误的能力强于一次生成正确答案的能力**（评估-生成不对称），多反思一轮就多抓一批错 |
| **Reflexion**（框架） | 执行 → 环境反馈（报错/测试失败）→ 语言化反思 → 带着反思重试 | 把"试错-反馈"循环从人类手里接过来；适合**结果可客观验证**的任务（代码/数学/游戏） |
| **Reflect-Retry-Reward**（2025） | 失败 → 生成反思 → 带反思重试 → 成功则奖励反思 token | 用 RL 教模型"反思得更好"，只有二元反馈也能自我提升 |
| **OpenAI 官方 Cookbook 循环** | 基线 Agent → 人类反馈或 LLM-as-judge → 元提示词改 Agent → 评估 → 循环 | 改的不是权重，是提示词/配置——企业落地版自进化 |

**关键数字与细节**：
- Self-Refine 原论文：7 类任务平均 **+20% 绝对提升**（5%-40% 区间），零训练数据、零外部工具
- **必须保留完整迭代历史**（所有旧版本+批评意见）——消融实验显示去掉历史会重复犯同样的错
- 反思提示三步：错误识别 → 原因分析 → 修正生成；**2-3 轮即停**，防无限递归烧钱
- 对照 [[2026-08-22-多智能体神话破灭]]：一个会反思的单 Agent，常常胜过一群不反思的 Agent

→ 与 [[ReAct与Agent设计模式]] 的 Reflection 模式同源（那里是模式简介，这里补齐方法谱系和数字）；与层面 4（策略进化）的分界：**这些不改权重，改的是上下文里的自我反馈**。

## 四、清华 AIR 的三层进化理论

清华大学刘洋教授团队提出"可进化智能体"框架，从三个层面展开：

| 层面 | 进化目标 | 核心能力 |
| --- | --- | --- |
| 单智能体"智商"进化 | 任务能力提升 | 从试错中学习更优解题策略，积累领域技能 |
| 单智能体"情商"进化 | 交互能力提升 | 理解用户情绪和意图，调整沟通方式，建立信任 |
| 多智能体"组织"进化 | 协作能力提升 | Agent 群体分工优化、角色涌现、组织结构自适应 |

> 刘洋教授提出智能体进化的基本准则——**人类、环境与智能体的统一对齐**。未来随着智能体群体在大规模环境中持续协作进化，或将迎来"第二次智能涌现"。

## 五、现实案例

| 项目 | 做了什么 | 自进化体现 |
| --- | --- | --- |
| **Karpathy autoresearch** | 开源文献调研 Agent | 完成调研后把有效搜索策略沉淀成工作流，下次更高效 |
| **Hermes Agent** (Nous Research) | 内置自主学习能力 | 自己写 MEMORY.md 和 USER.md，从交互中持续更新 |
| **MemOS** (中国电信研究院) | 给 Agent 装"记忆操作系统" | 把记忆从零散功能提升为系统级资源，自动抽取/组织/检索/更新/共享 |
| **SEED** (清华等) | on-policy 自我蒸馏 | Agent 复盘自己轨迹，提炼事后技能作为训练信号内化进参数 |
| **奇点逃逸 Nexus** | AI 原生团队协作系统 | 从每次协作中"有证据地变强"，三环节：真实反馈→独立评测→治理采用 |
| **Codely CLI Skills** | Agent 技能包系统 | 每个技能是 SKILL.md（指令+资源+触发条件），可创建/修改/版本管理 |
| **AgentEvolver** (arXiv 2511.10395) | 完全自主三环框架 | **自出题、自解题、自总结经验**，全链路无需人工标注 |
| **SkillOS / SKILL0** (2026) | 技能库管理系统 | 训练专门的 **Curator**：通过 RL 学"如何增删改技能库"，而非学"如何使用技能"——Executor 冻结只训 Curator |
| **Co-Evolution Iteration** | Skill 与 Test 共同进化 | 类比 TDD：Skill 过不了 Test 可能是 Test 不合理，两者互相牵制收敛到"高质量 Skill + 高严谨度 Test"稳态 |
