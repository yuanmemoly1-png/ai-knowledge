# DSH-02 · Cordis 插件化思想

> [!note] 一句话定义
> **DSH 不是"一个写死的大程序"，而是用 Cordis 这个插件框架，把"所有能力"都做成可插拔的小零件。** 工具是插件、技能是插件、人设是插件、连"沙箱""审批"这些安全设施也是插件。Cordis 就是拼这些零件的底座。

## 先认识 Cordis

**Cordis**（`@deepseek-ai/cordis`）是一个**插件框架**——它的唯一工作，就是"把很多个小插件，装进同一个运行时，让它们能互相借力、又不互相打架"。

> [!example] 生活比喻：插线板 + 电器
> - Cordis = 那根**插线板**（底座），只管通电和分配。
> - 每个插件 = 一个**电器**（台灯、电扇、充电器），各干各的活。
> - 你往插线板上插什么，这间屋子就有哪些功能。
> - DSH = 把插线板、电器清单、以及"哪间屋插什么"全部配好的一整套方案。

所以 DSH 的能力不是写死的，而是**"配"出来的**：想给 Agent 加个"查天气"能力，就多插一个插件；想关掉，就拔掉。

## 一个插件长什么样

在 DSH 的配置文件（`cordis.yml`）里，一个插件就是**列表里的一行**。比如给"标准模式"预设加"任务清单工具"这一行：

```yaml
- id: tool-todo                # 这行插件的名字（唯一）
  name: '@deepseek-ai/dsh-tool-todo'   # 它对应哪个 npm 包
  config:
    allowParallelInProgress: true       # 给这个插件的配置
```

每一行最常用的几个字段：

| 字段 | 含义 | 类比 |
| --- | --- | --- |
| `id` | 这一行的唯一编号 | 这台电器的"插座位号" |
| `name` | 对应哪个插件包（npm 包名） | 电器型号 |
| `config` | 给这个插件的参数 | 电器的旋钮/档位 |
| `disabled` | 是否禁用（true = 拔掉） | 插着但不通电 |

> [!tip] 记住这个词：**row（行）**
> 后文说"一个插件行 / plugin row"，指的就是配置文件里 `- id: ...` 开头的那一整块。**DSH 的世界里，一行 = 一个能力。**

## 插件怎么"干活"：apply 生命周期

每个插件都是一个 JavaScript 函数，入口叫 `apply(ctx)`。它的套路是：

```js
// 一个插件的骨架（伪代码，看懂意思即可）
function apply(ctx) {
  // 1. 向别的插件要东西（声明依赖，见下面"服务"）
  // 2. 干自己的活：注册工具 / 注册技能 / 注入人设……
  // 3. 返回一个"清理函数"，保证能被安全拔掉
  ctx.effect(() => {
    // 拔掉这个插件时要撤销的副作用（如：删掉刚挂的定时器）
  })
}
```

核心铁律：**每个副作用都必须能撤销**。这样插件才"可插拔"——开机时插上，关机/更新时能干净地拔掉，不留垃圾（[[DSH-06-动态插件运行时扩展]] 里这条会反复出现）。

## 三个关键词：服务 / 事件 / 依赖

插件之间靠三样东西协作：

| 词 | 是什么 | 类比 |
| --- | --- | --- |
| **Service（服务）** | 一个插件"提供"的东西，别的插件"借用" | 楼里的公共水电：一家提供，家家可接 |
| **Event（事件）** | 一个插件"广播"的消息，别的插件"收听" | 楼里的广播喇叭：响一声，想听的都听见 |
| **inject / 依赖** | 一个插件"点名要求"某个服务必须存在 | 电器标签上写"必须 220V 才能用" |

代码上的对应：

```js
return {
  inject: ['requiredService'],   // 硬依赖：没有它，这个插件就一直等着
  apply(ctx) {
    ctx.requiredService.doSomething()      // 直接用它
    const optional = ctx.get('optionalService')  // 软依赖：有就用，没有就跳过
    if (optional) optional.doSomething()
  },
}
```

> [!warning] 两条纪律（新手最容易踩）
> - **读服务用 `ctx.get('名字')`，并默认它可能不存在**；只有在"没它我根本活不了"时才写进 `inject`。
> - **不要直接 `ctx.某个服务` 去拿没声明的东西**——声明了才能拿，否则拿不到。

（完整词汇对照见 [[DSH-05-能力词汇表]]。）

## 为什么这套设计这么牛

1. **可插拔**：加能力 = 加一行，删能力 = 删一行或 `disabled: true`，不用改核心代码。
2. **可组合**：多个 `cordis.yml` 叠起来（见 [[DSH-04-配置文件与Preset结构]]），不同套餐复用同一批插件。
3. **可隔离**：用 `realm`（隔离域）让两个插件各自的"私有实例"不撞车（见 [[DSH-03-两个平面Host与Preset]]）。
4. **可回收**：生命周期由 `ctx.effect` 管着，插拔不留垃圾。

> [!tip] 一眼记住
> **DSH = 插线板(Cordis) + 一堆电器(插件) + 电路图(配置文件)。** 你看到的"我的工具、我的技能、我的性格"，拆开全是插件。
