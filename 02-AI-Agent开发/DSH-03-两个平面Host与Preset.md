# DSH-03 · 两个平面：Host 与 Preset

> [!note] 一句话定义
> DSH 把"这栋楼里的所有插件"分成**两层（两个平面）**：
> - **HOST 组合** = 整栋楼的公共设施，**所有会话共用一份**。
> - **AGENT PRESET** = 每一户自己的装修，**只属于当前这一个 Agent 会话**。
>
> 判断一个能力该放哪，看一句话：**"它是大家共用的，还是这一户私有的？"**

## 生活比喻：一栋公寓楼

```
        ┌────────────────────────────┐
        │       HOST 组合（物业）      │
        │  水管、电网、电梯、大门门禁    │
        │  （全楼共用一份，坏了全楼遭殃） │
        └────────────────────────────┘
              │  供所有住户使用
   ┌──────────┼──────────┐
   │ 住户A      │ 住户B      │ 住户C
   │ (Preset)   │ (Preset)   │ (Preset)
   │ 自己的家具  │ 自己的家具  │ 自己的家具
   └──────────┴──────────┴──────────┘
```

- **物业管的事（HOST）**：水电、电梯、门禁——**全楼一份**，谁住进来都用它。
- **自己装修的事（Preset）**：沙发、书架、墙纸——**每户各买各的**，互不影响。

对应到 DSH：

| | HOST 组合（物业） | AGENT PRESET（住户装修） |
| --- | --- | --- |
| 类比 | 公共设施 | 私有装修 |
| 共享范围 | 所有会话共用一份 | 只属于当前这一个会话 |
| 放什么 | 注册表、持久化存储、沙箱与审批、模型路由、子代理注册表 | 工具、技能、人设(persona)、提示词片段 |
| 举例 | 文件系统沙箱、权限审批、模型选择 | "我"能读文件、"我"会查网页、"我"的性格 |

## HOST 组合里具体有什么

这些是"地基级"设施，必须进程级共享，不能每个会话各搞一套（否则会打架）：

- **注册表（registries）**：工具的"总目录"、技能的"总目录"、子代理的"花名册"——所有会话往同一个目录里登记。
- **持久化（persistence）**：把会话数据存下来，跨会话还在。
- **沙箱 + 审批（sandbox / approval stack）**：限制我能碰哪些文件、危险操作要你点头。
- **模型路由（model route）**：决定我连的是哪个大模型。
- **子代理注册表与后端（subagent registry）**：我派"子代理"干活时用的花名册和后台。

> [!example] 为什么这些必须"共用一份"
> 想象"子代理花名册"如果每户各印一本：A 户登记了一个"查资料子代理"，B 户的花名册上却没有——那么 A 派出去的活 B 就认不得。所以这类东西只能放 HOST，全楼一本。

## PRESET 里具体有什么

这些是"这户 Agent 自己的"东西，每个会话可以不一样：

- **工具（Tools）**：这户 Agent 能调用的函数（读文件、查网页、跑命令……）。
- **技能（Skills）**：这户 Agent 能翻的"操作手册"（按需加载的指令集）。
- **人设（persona）**：这户 Agent 的自我介绍和身份。
- **提示词片段（prompt sections）**：额外塞给模型的规则（比如"你在计划模式"）。

> [!tip] 一句话判断法
> 拿到一个能力，问一句"**除了这个 Agent，还有谁会读它？**"
> - 别人也会读 / 全进程只有一份 → 放 **HOST**。
> - 只有这一个 Agent 读 → 放 **PRESET**。

## realm / isolate：给私有实例"隔间"

同一个插件，HOST 和不同 PRESET 都可能在用。怎么保证"我的实例"和"你的实例"不串味？答案是 **realm（隔离域）**。

```yaml
- id: planning               # 一个"组"，把里面几个插件圈成一个私有隔间
  name: cordis:group
  group: true
  isolate:                   # 这个隔间里，这些服务是"本户私有实例"
    planMode: true
  config:
    - id: plan-mode
      name: '@deepseek-ai/dsh-plan-mode'
```

- **没有 isolate**：服务发到"根域"，全进程共用一份——两个 preset 发同名服务会**撞车报错**。
- **加了 isolate**：这个服务变成"这户自己的私有实例"，跟别的 preset 互不干扰。

> [!warning] 新手最该记住的一句
> 一个会"提供服务"的插件行，**必须待在带 `isolate` 的组里**（或放 HOST）。否则它跑进全局，另一个 preset 发同名服务就冲突，宿主读到的也可能是"别人的实例"。这正是真实配置文件里 `standard` 预设那一大堆注释在反复叮嘱的事。

## 两个平面 × 三个运行位置

把"平面"和"运行位置"合起来，DSH 里的插件最终落在三处：

1. **HOST（Node.js 进程）**：文件、网络、命令、会话管理——重量级、共享。
2. **PRESET / Agent 侧**：工具、技能、人设——这个 Agent 自己的。
3. **CLIENT（浏览器页面）**：主题、布局、工具卡片、插槽 UI——只管"长什么样、怎么交互"。

> [!tip] 一眼记住
> **公共设施归物业(HOST)，自家装修归住户(Preset)，门面装修归前台(Client)。** 加能力前先问一句"这是谁的"。
