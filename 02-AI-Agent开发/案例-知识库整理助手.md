# 案例：知识库整理助手（提示词设计工作笔记）

> [!note] 这个案例是干嘛的
> 用 [[提示词工程-写作方法论]] 的"六步流水线"设计一个真实项目：**把文件/视频资料整理进知识库，并支持问答调用**。这篇是工作笔记，随设计迭代更新。

## 需求拆解（第 1 步）

| 需求 | 具体化 | 关键决策 |
| --- | --- | --- |
| 能检索文件 | 文本直接读入 | — |
| 能检索视频 | 视频 → **转文字 + 抓关键帧** 后再处理 | 视频不能直接读，必须先转录 |
| 分类归纳 | **按主题建文件夹**（AI → AI 文件夹，数学 → 数学文件夹） | 分类标准 = 主题 |
| 需要时调用 | **问答式检索**：问"提示词工程是什么" → 库中查找 → 汇报；**没有就说"库中没有这方面知识"** | = RAG 问答 |
| 存储 | md 存资料 + 文件夹分类 + 索引/标签 + **向量库**做语义检索 | 见下方存储对比 |

## 存储对比：md / json / 向量库（先想清楚再动手）

| 存储方式 | 是什么 | 比喻 | 谁读 |
| --- | --- | --- | --- |
| md 文件 | 原始资料 | 书 | 人 |
| json 索引 | 路径/主题/标签/摘要的目录 | 图书目录卡片 | 程序 |
| 向量库 | 按"意思相近"检索 | 懂语义的检索员 | 程序 |

> [!important] 不是三选一，是分工
> 资料照常存 md；文件夹负责主题分类；索引/标签管"哪份归哪类"；向量库专门负责"问问题 → 找相关片段"。向量库是**检索器，不是仓库**。
>
> 进阶顺序：先关键词搜索（grep）跑通（参考 [[小白课-实战RAG迷你版]]）→ 内容变多、问题变"绕"后再上向量库（[[Embedding向量嵌入]]）。

## 系统流程（标准 RAG 四段式）

```text
文件 ──► 直接读入
视频 ──► 转文字 + 抓关键帧        ← 摄入
              │
              ▼
        按主题建文件夹              ← 分类
              │
              ▼
        打标签 + 摘要 + 向量化入库   ← 索引
              │
              ▼
        提问 → 检索 → 汇报           ← 检索 + 回答
        （没有就说"库中没有"，不编造）
```

## 模块映射（第 2 步）——拆成两套提示词

系统分两个阶段，各写一份提示词（这正是"拆需求 → 拆模块 → 逐个写"的产物）：

### 模块 A：整理助手（摄入 + 分类 + 建索引）

```text
你是知识库整理助手，负责把新资料加工进知识库。

工作流程：
1. 读入资料：文本文件直接读取；视频先用工具转成文字，并抓取关键帧
2. 判断主题：根据内容判断属于哪个主题（AI、数学、Python…）
3. 建文件夹：把文件归入对应主题文件夹，没有就新建
4. 生成元数据：为每份资料写一句话摘要，打 3-5 个标签
5. 更新索引：把路径、主题、标签、摘要写入索引，并向量化入库

规则：
- 主题拿不准时，先归入"待定"并问我
- 不要修改原始文件的内容
```

### 模块 B：问答助手（检索 + 回答）

```text
你是知识库问答助手。

用户提问时：
1. 先在知识库中检索相关片段
2. 基于检索到的内容回答，并注明来源（哪个文件）
3. 检索不到相关内容时，明确说"库中没有这方面知识"，绝不编造

规则：
- 回答必须基于检索结果，不凭空发挥（防幻觉）
- 引用来源文件，方便我核对
```

## 这份设计用到了哪些套路（对照 [[提示词工程-真实案例拆解]]）

| 套路 | 用在哪 |
| --- | --- |
| 身份锚定（套路 1） | 两套提示词的开头"你是…助手" |
| 流程步骤化 | 整理助手的 1-5 步（对应"分步骤"技巧） |
| 行为约束到动词（套路 3） | `不要修改原始文件`、`绝不编造` |
| 边界声明（套路 6） | `没有就说"库中没有"`（对应"允许说不知道"） |
| 防幻觉 | 问答助手"必须基于检索结果" = RAG 思想（[[RAG检索增强生成]]） |
