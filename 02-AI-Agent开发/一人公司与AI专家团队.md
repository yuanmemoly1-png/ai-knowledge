# 一人公司如何拥有自己的 AI 专家团队

> [!note] 一句话本质
> 一人公司的正确姿势不是"一个人干五个人的活"，而是**你当导演，雇一队 AI Agent 当员工**——每个 Agent 管一摊（营销/销售/客服/财务），你只做决策和质检。核心公式：**创始人（决策层）+ 智能体矩阵（执行层）**。

## 一、为什么 2026 年这事成立了

| 旧模式 | 新模式 |
| --- | --- |
| 一个人切换五个角色，时间永远不够 | 一个导演指挥 Agent 团队，你只决策 |
| AI 是"写文案的辅助插件" | AI 能"看懂屏幕、跨系统执行、直接帮你做" |
| 每个职能招一个人 | 业务流程拆成工作流，交给数字员工 |

关键能力变化：现代 Agent 具备**任务拆解 → 工具调用 → 结果校验 → 异常处理**的完整闭环（见 [[Agent核心架构]]），且 24 小时在线、不请假、不离职——任务标准完全由你定义。

## 二、核心架构：两层分工（最重要的设计思想）

来自 OpenClaw + Codex/Claude Code 集群的实战方案：

| 层级 | 角色 | 上下文装什么 |
| --- | --- | --- |
| **编排层**（如 OpenClaw 管家） | 懂业务的"总经理" | 客户数据、会议记录、历史决策、业务战略 |
| **执行层**（Codex/Claude Code 等） | 干活的"员工" | 代码库、类型定义、测试文件 |

**为什么必须两层？——上下文窗口是零和博弈**：

```text
填满代码     → 没空间装业务背景
填满客户历史 → 没空间装代码库
```

所以专业化来自**上下文分配**，而非依赖不同模型。这与 [[DSH-03-两个平面Host与Preset]] 的 HOST/Preset 分层思想同源：公共设施归物业，住户装修归住户——**谁需要什么上下文，就给谁什么上下文**。

## 三、一个真实 8 步工作流（需求到交付）

1. 客户需求进来 → 与编排 Agent（如 Zoe）对话拆解
2. 编排 Agent 先做三件事：补充 API 额度解客户阻塞 / 从生产库拉配置（**只读权限，执行层永远没有**）/ 携带完整上下文派生一个执行 Agent
3. 执行 Agent 在自己的干净上下文里干活（对应 Claude Code 的 Subagent 机制，见 [[ClaudeCode源码拆解]]）
4. PR 备好后通过 Telegram 通知创始人
5. **决策权永远在人**：接不接单、合不合并，创始人拍板

## 四、三个成熟度递进的玩法

| 玩法 | 人做什么 | AI 做什么 | 适合 |
| --- | --- | --- | --- |
| **超级个体** | 主导工作，AI 辅助 | 写作/搜索/总结 | 起步期 |
| **内容工厂** | 手机上做/不做决策（Telegram 推选题） | 全链路：选题→去重→研究→大纲→初稿→发布 | 内容创作者 |
| **Agent 集群** | 只做战略决策和验收 | 编排层+执行层全自动 | 有业务系统的开发者 |

**内容工厂的精髓设计**（YouTube/公众号自动化管线）：
- **双源交叉验证**选题：Web 新闻 + X 热议同时升温才算好选题
- **语义去重**：SQLite 存历史话题 + 向量嵌入算相似度——"上周讲过 GPT-5 发布"换个标题也逃不掉
- **90 天滚动目录**：既去重又保主题多样性

## 五、别忽视的平衡：真人与多 Agent 的边界

- **真人助手仍有价值**：跟客户沟通、谈价格、对接渠道——这些"非核心但必须有人干"的活，AI 干不了（俗人六哥的三层架构：决策层=你 / 执行层=真人助手 / 生产层=AI）
- **多 Agent 不是银弹**：[[2026-08-22-多智能体神话破灭]] 证明团队会稀释专家能力——一人公司场景恰好是**多 Agent 的正确用法**：任务天然独立（营销/客服/财务各管一摊）、子任务间弱依赖、每个 Agent 有干净的专属上下文。对照 [[ReAct与Agent设计模式]] 的模式选择速查
- **现成产品**：腾讯 WorkBuddy 已内置 29 领域 141 位 AI 专家、9 个"一人公司部门"（产研/市场/SEO/变现/财务…）——不想自己搭可以先体验它，理解"角色分工"的感觉

## 六、对你的意义（连接你的路线）

1. **学习路线照旧**：这套玩法的地基就是你正在学的东西——Agent 架构（[[Agent开发总览]]）、多智能体（[[CrewAI多智能体]]）、MCP 工具接入（[[MCP协议实战]]）
2. **你的知识库就是编排层的雏形**：[[知识图谱总览]] + 自进化系统（[[Agent自进化]]）= 你自己的"业务上下文层"；将来接上执行层 Agent，就是一个最小的一人公司架构
3. **接单变现的新叙事**：[[Agent开发工程师路线]] 的求职方向之外，"帮小老板搭 AI 员工团队"本身已是市场（[[2026-08-22-AI人才价值重估]] 说的"能把模型变成稳定业务系统"的人）

## 面试价值

被问"**多智能体系统的实际应用场景**"时：

> "一人公司是当下最典型的落地场景——编排层 Agent 持有业务上下文（客户/决策/战略），执行层 Agent 拿干净上下文干活，两层分工的根因是**上下文窗口的零和博弈**。设计要点三个：权限分级（执行层只有只读生产库权限）、决策权留人（Telegram 通知+人拍板）、任务天然独立所以避开了多智能体的'专业知识稀释'问题。"
