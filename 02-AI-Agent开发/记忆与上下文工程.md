# 记忆与上下文工程

Agent 的「记忆」本质上是**往有限的 [[上下文窗口]] 里放什么内容**的问题。近年来业界把这件事从「写好一句 Prompt」升级为 **Context Engineering（上下文工程）**：系统性管理喂给模型的全部信息——系统提示、对话历史、工具结果、检索内容、记忆——让模型在正确的时间看到正确的信息。

## 短期记忆：单次任务内

### 1. 全量对话历史

最简单：把所有消息原样保留。

```python
messages.append({"role": "user", "content": user_input})
messages.append({"role": "assistant", "content": reply})
```

问题：对话一长就撑爆上下文窗口，Token 成本也线性上涨。

### 2. 滑动窗口

只保留最近 N 轮，旧的直接丢弃：

```python
def trim_history(messages, max_turns=10, keep_system=True):
    system = messages[:1] if keep_system and messages[0]["role"] == "system" else []
    body = messages[1:] if system else messages
    return system + body[-max_turns * 2:]   # 每轮含 user + assistant 两条
```

缺点：早期的关键信息（用户姓名、任务目标）会被遗忘。

### 3. 摘要压缩

窗口满了以后，让 LLM 把旧对话压缩成一段摘要，替代原始消息：

```python
def compress_history(old_messages, llm):
    summary = llm.generate(
        "把以下对话压缩成 200 字摘要，保留：用户目标、已确认的事实、待办事项。\n"
        + format_messages(old_messages)
    )
    return [{"role": "system", "content": f"前情摘要: {summary}"}]
```

实践中最常用的是 **摘要 + 最近几轮原文** 的混合策略：既保留远期要点，又不丢近期细节。

## 长期记忆：跨会话持久

| 方案 | 适合存什么 | 怎么取 |
| --- | --- | --- |
| 向量数据库 | 用户偏好、历史经验、领域知识 | 语义相似度检索（见 [[RAG检索增强生成]]、[[Embedding向量嵌入]]） |
| 文件系统 | 项目状态、任务清单、结构化档案 | Agent 用读写文件工具直接操作 |
| KV / 关系数据库 | 精确事实（用户 ID、设置项） | 按键精确查询 |

典型模式：每轮对话前，用当前用户输入去向量库检索 top-k 条相关记忆，拼进 system prompt。

```python
def build_context(user_input, memory_store, top_k=3):
    memories = memory_store.search(user_input, k=top_k)   # 向量检索
    memory_block = "\n".join(f"- {m.text}" for m in memories)
    system = f"你是助手。关于该用户你记得:\n{memory_block}"
    return [{"role": "system", "content": system}]
```

## 上下文污染与对策

Agent 跑久了，上下文会被各种垃圾填满，导致模型「注意力涣散」——这就是上下文污染。常见污染源和对策：

| 污染源 | 表现 | 对策 |
| --- | --- | --- |
| 工具结果过长 | 一次搜索塞回 5000 字网页 | 截断到前 N 字符，或先让小模型提炼 |
| 失败的尝试 | 反复报错的工具调用留在历史里 | 失败后压缩成一行「尝试过 X，失败原因 Y」 |
| 无关信息堆积 | 子任务 A 的细节干扰子任务 B | 子任务用独立上下文（sub-agent），只回传结论 |
| 过期目标 | 用户改了需求，旧目标还在 | 显式维护「当前目标」字段，每次规划前重申 |

> [!tip] 一个朴素但极有效的原则
> 上下文里的每一个 Token 都应该为「下一步决策」服务。定期问自己：这条信息删了会影响后续决策吗？不会就删掉或压缩。

## 工程实践清单

1. 每条工具 observation 设置最大长度（如 2000 字符），超限截断
2. 对话超过阈值就触发摘要压缩
3. 长期记忆写入前做去重和时效检查，避免库里堆满矛盾信息
4. 重要事实（用户身份、任务目标）固化在 system prompt，不依赖历史消息
5. 多 Agent 场景给每个子 Agent 独立上下文，只传递必要结论
