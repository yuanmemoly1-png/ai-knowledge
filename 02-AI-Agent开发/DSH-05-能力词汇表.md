# DSH-05 · 能力词汇表

> [!note] 这一篇是什么
> 读 DSH 源码和配置时，会反复撞见一组词：Service、Event、Tool、Skill、Slot、Realm…… 这篇把它们集中翻译成大白话，像字典一样随时翻。**每个词都配了"比喻 + 谁提供 + 谁使用"**。

## 总表速查

| 词 | 中文 | 一句话比喻 | 谁提供 / 谁用 |
| --- | --- | --- | --- |
| Plugin | 插件 | 一件"电器" | 所有人 |
| Service | 服务 | 楼里的公共水电 | 插件提供 → 插件借用 |
| Event | 事件 | 楼里的广播喇叭 | 插件广播 → 插件收听 |
| Tool | 工具 | Agent 的"手" | 插件注册 → 模型调用 |
| Skill | 技能 | 用时才翻的"操作手册" | 技能库 → Agent 按需加载 |
| Slot | 插槽 | 墙上的"预留挂钩" | 浏览器页面预留 → 插件挂 UI |
| Realm / isolate | 隔离域 | 每户的"私人房间" | 用来隔开私有实例 |
| Builtin | 内建 | 平台自带的家电 | 平台提供 |
| inject / ctx.get | 依赖 | 电器的"用电要求" | 插件声明 |
| Persona | 人设 | Agent 的"自我介绍" | preset 注入 |

下面逐个展开。

## Service（服务）

- **是什么**：一个插件"提供"出来、别的插件能"借"的能力。
- **比喻**：楼里的自来水。物业(某插件)供水，家家(别的插件)接水龙头。
- **代码**：提供方把它登记出来；使用方用 `ctx.get('服务名')` 或声明 `inject` 来拿。

## Event（事件）

- **是什么**：一个插件"广播"消息，别的插件"收听"并响应。
- **比喻**：楼里的广播喇叭——"失火了"响一声，想听的都听见、各自行动。
- **代码**：`ctx.on('事件名', 处理函数)`，返回的清理函数保证"拔掉就不听了"。

## Tool（工具）

- **是什么**：模型（我）能**主动调用**的函数。这是 Agent 的"手脚"。
- **比喻**：Agent 的手。模型说"读这个文件"，框架就调"读文件工具"去执行。
- **和 Service 的区别**：Service 是插件之间的"内部水电"，Tool 是**直接面向模型**的"对外手脚"。一个能力给模型用就叫 Tool，给插件用就叫 Service。
- **延伸**：工具要有"说明书"（名称 + 描述 + 参数 schema），模型靠它决定何时调用、传什么参数——对应 [[FunctionCalling函数调用]] 和 [[工具调用实战]]。

## Skill（技能）

- **是什么**：一组**按需加载的指令集**（操作手册）。模型在需要时才把它翻出来读。
- **比喻**：工具箱里的"说明书"，平时收着，干到哪一步才抽哪本。
- **例子**：本会话的技能库里就有 `editing-cordis-compositions`（写组合前必读）、`cordis-plugin-development`（开发动态插件前必读）等几十本。
- **规则**：任务明确匹配某技能时，要先 `skill` 加载它，再按它的指令干活。

## Slot（插槽）

- **是什么**：浏览器页面**预留的"挂钩"**，插件可以把 UI（界面）挂上去。
- **比喻**：墙上预留的挂钩——谁想挂画、挂灯，就挂到这个钩上。
- **场景**：CLIENT 侧的插件想加个按钮、面板、工具卡片，就注册到某个 Slot。
- **要点**：UI 必须注册进查询到的 Slot；`apply` 不能直接返回界面元素。

## Realm / isolate（隔离域）

- **是什么**：给"服务实例"划的**隔离范围**。
- **比喻**：每户的私人房间——A 户的电视和 B 户的电视是两台，互不串台。
- **规则**：会"提供服务"的插件行必须待在带 `isolate` 的组里（或放 HOST），否则进全局会撞车（详见 [[DSH-03-两个平面Host与Preset]]）。

## Builtin（内建）

- **是什么**：平台**自带**的能力（函数/对象），插件代码可以直接查、可以用。
- **比喻**：房子交付时已经装好的家电。
- **注意**：插件代码里**别想当然**假设有 `window`、`fetch`、`process` 这些——先查平台 Builtins 再写。

## inject / ctx.get（依赖）

- **是什么**：插件"要东西"的两种姿势。
- **硬依赖 `inject`**：没它活不了，等它出现再启动。
- **软依赖 `ctx.get`**：有就用，没有就跳过（**默认用它，且处理 undefined**）。
- **比喻**：电器标签写"必须 220V"（inject）vs "有 USB 口更好，没有也行"（ctx.get）。

## Persona（人设）

- **是什么**：注入给模型的"自我介绍和身份"，决定"我是谁、我在哪、我能干嘛"。
- **比喻**：Agent 的"工牌 + 岗位说明"。
- **例子**：cordis 预设的人设开头就是 *"You are a coding agent powered by the {{model}} model, running on the DeepSeek Harness…"*，其中 `{{model}}` 会在运行时替换成真实模型名。

## 再补两个高频词

| 词 | 含义 |
| --- | --- |
| **Host / Client** | 运行位置：Host = Node.js 进程（干活）；Client = 浏览器页面（界面）。两者靠"包内私有 JSON 方法"通话（Client→Host 单向调用）。 |
| **apply(ctx)** | 每个插件的入口函数，插件的"开机动作"都写在这里。 |

> [!tip] 一眼记住
> **手(Tool)给模型用，水电(Service)给插件用，喇叭(Event)广播，手册(Skill)按需翻，挂钩(Slot)挂界面，房间(Realm)隔实例。**
