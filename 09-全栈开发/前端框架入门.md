# 前端框架入门

## 为什么需要框架

用原生 JS 写页面（[[JavaScript入门]] 里的方式），功能一多就会撞墙：

| 原生 JS 的痛点 | 具体表现 |
| --- | --- |
| 手动操作 DOM | 每改一个数据都要 `querySelector` + 改 `textContent`，代码又长又易错 |
| 数据和页面脱节 | 数据变了，页面不会自动更新，要自己记住哪里要刷 |
| 代码无法复用 | 三个页面都有「待办卡片」，就得复制三份 HTML |
| 状态混乱 | 数据散落在各个变量和 DOM 里，改一处坏三处 |

**前端框架（React、Vue 等）** 的核心解法只有一句话：**你只描述「数据长什么样，页面就该长什么样」，框架负责数据变化时自动更新页面。**

## 组件化思想：像搭积木一样做页面

框架把页面拆成一个个**组件（Component）**——带自己的结构、样式和数据，可以反复使用的积木块：

```text
页面
├── 导航栏组件
├── 待办输入框组件
└── 待办列表组件
    ├── 待办卡片组件 ×1
    ├── 待办卡片组件 ×2
    └── 待办卡片组件 ×3   （同一个组件，传不同数据）
```

- 父组件通过 **props（属性）** 把数据传给子组件——相当于 Python 函数的参数
- 组件内部的 **state（状态）** 一变，框架自动重新渲染对应部分——不用手动操作 DOM

## React vs Vue

| 维度 | React | Vue |
| --- | --- | --- |
| 出品 | Meta（Facebook） | 尤雨溪（华人开发者） |
| 生态重心 | 国际市场、大厂、React Native（跨端 App） | 中国生态极繁荣，中文文档和教程多 |
| 写法 | 一切是 JS，HTML 写在 JS 里（JSX） | 模板接近原生 HTML，上手坡度更缓 |
| 学习曲线 | 概念较多（JSX、Hooks） | 对 0 基础更友好 |
| 国内岗位 | 大厂多 | 中小厂、外包、创业公司非常多 |

> [!tip] 0 基础选型建议
> **不要纠结，任选其一深入**。两者概念（组件、props、状态）是相通的，学会一个再转另一个只要几天。如果非要一个答案：目标是做个人产品、快速见效选 **Vue**（中文资料多、模板直观）；目标是大厂求职或做跨端 App 选 **React**。

## 最小 React 组件

```jsx
// 一个函数就是一个组件，返回的 JSX 描述页面结构
function TodoCard({ title, done }) {   // props 通过参数传入
  return (
    <div className="todo-item">
      <span style={{ textDecoration: done ? "line-through" : "none" }}>
        {title}                        {/* 大括号里写 JS 表达式 */}
      </span>
    </div>
  );
}

// 使用：像写 HTML 标签一样使用组件
function App() {
  return <TodoCard title="学 React" done={false} />;
}
```

## 最小 Vue 组件

```vue
<!-- 一个 .vue 文件分三块：模板、逻辑、样式 -->
<template>
  <div class="todo-item">
    <span :class="{ done: done }">{{ title }}</span>
  </div>
</template>

<script setup>
// 声明这个组件接收哪些 props
defineProps({ title: String, done: Boolean });
</script>

<style scoped>
.done { color: #999; text-decoration: line-through; }
</style>
```

> [!note] 学习方式变了，本质没变
> 框架项目通常用 Node.js 的脚手架创建（`npm create vue@latest` 之类），不再是一个 html 文件直接打开。但你写的仍然是 HTML、CSS、JS 三件套——框架只是换了一种组织方式。所以 [[HTML与CSS入门]] 和 [[JavaScript入门]] 是框架的直接前置，跳不过去。

## 有了框架后，前后端如何分工

这就是 [[前端与后端]] 里说的经典分离架构：

```text
┌────────────────────────────┐      HTTP 请求（fetch/axios）
│ 前端（React/Vue）           │ ──────────────────────────►
│ 渲染页面、收集用户输入        │ ◄──────────────────────────
└────────────────────────────┘        JSON 数据
┌────────────────────────────┐
│ 后端（[[FastAPI后端实战]]）   │
│ 业务逻辑、读写数据库、调 LLM   │
└────────────────────────────┘
```

- 前端不再直接碰数据库，只调后端暴露的 [[API接口]]
- 后端不生成 HTML，只返回 JSON——同一套后端可以同时服务网页、小程序（见 [[微信小程序开发入门]]）、App
- 各端独立开发部署，用接口文档（FastAPI 自带的 `/docs`）对齐
