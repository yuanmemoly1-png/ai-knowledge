# 部署与上线

## 本地运行 vs 部署

在自己电脑上 `python app.py` 跑起来、浏览器访问 `http://127.0.0.1:8000`——这叫**本地运行**，只有你自己能用，电脑一关服务就停。

**部署（Deployment）/ 上线** 是把应用搬到一台 7×24 小时开机的服务器上，配上公开网址，让任何人随时能访问。从"能跑"到"别人能用"，中间这一步就是部署。

## 常见部署形态对比

| 形态 | 代表 | 优点 | 缺点 | 适合 |
| --- | --- | --- | --- | --- |
| 托管平台 | Vercel、Railway | 推代码自动部署，自带 HTTPS，免费额度 | 自由度低，超额度要付费 | 前端项目、小型后端、快速验证 |
| 云服务器（VPS） | 阿里云、腾讯云轻量服务器 | 完全掌控，想装什么装什么 | 要自己配环境、管安全 | 想认真学运维、长期运营的项目 |
| 小程序云托管 | 微信云托管 | 和小程序生态无缝衔接，免备案 | 绑定微信生态 | 微信小程序后端，见 [[微信小程序开发入门]] |
| 本地/内网 | 自己的电脑、公司内网 | 零成本、数据不出内网 | 只有局域网能用 | 内部工具、隐私敏感的 AI 应用 |

> [!tip] 新手路线
> 第一个项目建议从**托管平台**起步（推送 Git 代码就自动上线，见 [[Git与版本控制]]），等产品真的有人用了再考虑买云服务器。别一上来就折腾 Nginx、Docker 这些运维细节。

## 域名与 HTTPS

- **域名（Domain）**：给服务器 IP 起的易记名字。`api.example.com` 比 `47.96.12.34` 好记，也好换服务器。域名需要按年付费购买。
- **HTTPS**：网址前那把"小锁"，表示传输内容被加密，中间人偷看不到。现在它是**事实上的强制要求**：浏览器会对 HTTP 网站标"不安全"，微信小程序、App 上架都只允许 HTTPS 接口。
- 好消息：托管平台自动送你 HTTPS 证书；自建服务器可以用免费的 Let's Encrypt 证书。

```
用户浏览器 ──HTTPS 加密──▶ api.你的域名.com ──解析──▶ 服务器 IP:端口 ──▶ 你的 FastAPI 应用
```

## 一个 Python Web 应用的上线流程

以 FastAPI 应用（见 [[前端与后端]]）为例，上线大致五步：

1. **代码收尾**：敏感配置（API Key、数据库密码）全部改为环境变量读取，确认 `.gitignore` 已排除 `.env`，见 [[Git与版本控制]]。
2. **声明依赖**：生成 `requirements.txt`（`pip freeze > requirements.txt`），告诉服务器要装哪些库。
3. **推送代码**：`git push` 到 GitHub。
4. **连接平台**：在托管平台（如 Railway）绑定 GitHub 仓库，平台自动装依赖、启动应用。
5. **配置变量与域名**：在平台后台填入环境变量（把 `.env` 内容填进去），绑定自定义域名，HTTPS 自动生效。

上线后访问 `https://api.你的域名.com/hello`，全世界都能调你的接口了。

## 本地和线上的常见差异

很多"在我电脑上明明能跑"的事故，来自两类环境的差异：

| 差异点 | 本地 | 线上 |
| --- | --- | --- |
| 访问地址 | `127.0.0.1`，只有自己能访问 | 公网域名/IP，任何人可达 |
| 配置来源 | `.env` 文件 | 平台后台的环境变量（`.env` 不应上传） |
| 运行时长 | 你手动启动，关电脑就停 | 7×24 常驻，崩溃要自动重启 |
| 数据 | 测试数据，删了不心疼 | 真实用户数据，要备份、要谨慎迁移 |

> [!example] 经典翻车现场
> 把写死 `http://127.0.0.1:8000` 的前端直接上线，用户浏览器去访问"用户自己电脑的 8000 端口"，自然一片空白。前后端联调地址必须用环境变量区分本地和线上。

> [!warning] 上线前检查清单
> - **API Key 不进代码仓库**：只在服务器环境变量里配置，泄露一次损失惨重。
> - **关闭调试模式**：FastAPI 的 `--reload`、详细报错页面只在本地开，线上暴露错误细节等于给攻击者递地图。
> - **限制访问频率**：公开接口没有限流，被人刷爆 LLM API 账单就是一瞬间的事（状态码 429 的另一面，见 [[API接口]]）。
> - **先小范围测试**：发给几个朋友用，确认没问题再公开宣传。

## 上线之后还要做什么

部署不是终点，而是运营的开始：

1. **看日志（Logging）**：报错、慢请求都写在日志里，托管平台一般有日志面板，出问题先看它。
2. **盯账单**：服务器费 + LLM API 调用费，设好用量告警，避免一觉醒来天价账单。
3. **持续迭代**：改代码 → commit → push，托管平台自动重新部署，这正是 [[Git与版本控制]] 的价值。
4. **备份数据**：数据库定期备份，见 [[数据库入门]]，线上数据丢了可没有后悔药。

## 为什么这对 AI 开发很重要

AI 应用的部署有个特殊性：**模型本身通常不用你部署**——调 OpenAI/国产大模型的 [[API接口]] 即可，你部署的只是"中转后端 + 前端界面"。这让个人开发者也能上线一个 AI 产品，成本只有服务器费和模型调用费。完整的从零到上线实战见 [[用AI开发App全流程]]。
