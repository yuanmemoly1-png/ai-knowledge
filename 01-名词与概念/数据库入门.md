# 数据库入门

## 为什么需要数据库

数据存在变量里，程序一关就没了；存在文件（CSV、JSON）里，数据一多就没法查、多人同时写还会冲突。**数据库（Database）** 就是专门解决这三件事的软件：

1. **持久化**：关机重启数据还在。
2. **高效查询**：百万条记录里按条件查找，毫秒级返回。
3. **并发与安全**：多人同时读写不打架，还有权限控制。

## SQL vs NoSQL

| 维度 | SQL（关系型数据库） | NoSQL（非关系型数据库） |
| --- | --- | --- |
| 数据组织 | 一张张表，行和列，像 Excel | 文档（JSON）、键值对、图等，结构灵活 |
| 结构要求 | 先定义好表结构（Schema）再存 | 随存随改，每条数据字段可以不一样 |
| 查询语言 | 统一的 SQL 语言 | 各家自有查询语法 |
| 擅长 | 结构化、关系明确的数据（订单、用户） | 结构多变、海量读写（日志、聊天记录） |
| 代表 | SQLite、MySQL、PostgreSQL | MongoDB、Redis |

> [!note] 零基础怎么理解
> 用户注册、订单支付这种"字段固定、关系清晰"的数据用 SQL；AI 应用的对话历史、日志这种"每条长得不一样"的数据常用 NoSQL。两者经常在同一个项目里并存。

## 选型速查

| 数据库 | 类型 | 特点 | 适合场景 |
| --- | --- | --- | --- |
| SQLite | SQL | 一个文件就是一个库，零安装零运维 | 个人项目、原型、桌面/移动应用 |
| MySQL | SQL | 最流行的开源数据库，资料极多 | 网站、中小型后端 |
| PostgreSQL | SQL | 功能最强，支持向量扩展 pgvector | 严肃的生产项目、AI 应用 |
| MongoDB | NoSQL | 存 JSON 文档，结构灵活 | 内容管理、快速迭代的产品 |

> [!tip] 学习路径
> 从 **SQLite** 起步（Python 自带，不用装任何东西），需要多人访问或服务端部署时再换 MySQL/PostgreSQL，SQL 语法基本通用。

## 动手：Python sqlite3 增删改查

Python 标准库自带 `sqlite3`，无需安装任何东西：

```python
import sqlite3

conn = sqlite3.connect("notes.db")     # 连接数据库（文件不存在则自动创建）
cur = conn.cursor()

# 建表（只执行一次）
cur.execute("""
CREATE TABLE IF NOT EXISTS notes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    title TEXT,
    content TEXT
)
""")

# 增 Create —— 用 ? 占位符传参，防止 SQL 注入
cur.execute("INSERT INTO notes (title, content) VALUES (?, ?)",
            ("第一条", "学会 SQLite 了"))
conn.commit()                          # 写操作后必须提交

# 查 Read
cur.execute("SELECT id, title FROM notes WHERE title LIKE ?", ("%SQLite%",))
for row in cur.fetchall():
    print(row)                         # (1, '第一条')

# 改 Update
cur.execute("UPDATE notes SET content = ? WHERE id = ?", ("内容已更新", 1))
conn.commit()

# 删 Delete
cur.execute("DELETE FROM notes WHERE id = ?", (1,))
conn.commit()

conn.close()
```

四句核心 SQL 记住就够用了：`INSERT`（增）、`SELECT`（查）、`UPDATE`（改）、`DELETE`（删）。

## 向量数据库：AI 时代的新成员

传统数据库擅长**精确匹配**（"title 等于 X"），但 AI 应用需要**语义搜索**（"找出意思相近的文档"），这就是**向量数据库**的活：把文本通过 [[Embedding向量嵌入]] 变成向量，按"向量距离"找相似内容。

| 对比 | 传统数据库（如 SQLite） | 向量数据库（如 Chroma） |
| --- | --- | --- |
| 查什么 | 字段精确相等、范围比较 | 语义相似度（距离最近的 Top-K） |
| 数据形态 | 结构化的行和列 | 向量 + 原文 + 元数据 |
| 典型问题 | "id 为 42 的用户是谁" | "和这个问题意思相近的文档有哪些" |

Chroma 是最适合入门的向量数据库（pip 安装即用），完整示例见 [[RAG检索增强生成]] 笔记中的最小可运行示例。

> [!warning] 常见误区
> - **用文件代替数据库**：用户数据、账单这种重要数据别存 JSON 文件，没有并发保护，迟早出事。
> - **字符串拼接 SQL**：`f"WHERE name = '{name}'"` 会被 SQL 注入攻击，永远用 `?` 占位符传参。
> - **以为向量数据库能取代传统数据库**：两者是互补的——用户信息放 SQLite/MySQL，知识库向量放 Chroma。
