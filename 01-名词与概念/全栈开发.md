# 全栈开发

## 什么是全栈

**全栈开发（Full-Stack Development）** 指一个人（或一个角色）同时覆盖一个应用的全部技术层：用户看得见的界面、跑在服务器上的逻辑、存数据的数据库。这三层合起来叫"技术栈（Tech Stack）"，都能做的人叫**全栈工程师（Full-Stack Developer）**。

与之相对的是**专精分工**：前端工程师只做界面，后端工程师只做服务器逻辑，各管一段。

## 一个应用的三层分工

```
┌─────────────────────────────────────────┐
│ 前端 Frontend（用户看到、点到的部分）        │
│ 网页 / 小程序 / App 界面                  │
└──────────────┬──────────────────────────┘
               │ 通过 API 收发数据
┌──────────────┴──────────────────────────┐
│ 后端 Backend（服务器上的业务逻辑）          │
│ 登录校验、调用 LLM、处理订单              │
└──────────────┬──────────────────────────┘
               │ 读写数据
┌──────────────┴──────────────────────────┐
│ 数据库 Database（持久化存储）              │
│ 用户表、聊天记录、知识库                  │
└─────────────────────────────────────────┘
```

拿一个"AI 记账小程序"举例：

- **前端**：记账页面、图表展示，用户在手机上看到的全部东西。
- **后端**：接收记账请求、把消费描述发给 [[LLM大语言模型]] 做自动分类、返回结果。
- **数据库**：存下每一笔账单和分类结果，下次打开还能看到。

## 为什么 AI 时代全栈值得学

> [!note] 一个人也能做完整产品
> 过去全栈难在"每层都要精通"，学习成本极高。现在 [[VibeCoding方法论]] 改变了游戏规则：你不需要手写每一层代码，只需要**懂每层的职责、能描述清楚需求、会验收结果**，AI 编程工具（见 [[AI编程工具对比]]）帮你生成大部分代码。
>
> 全栈能力从"写代码的能力"变成了"架构理解 + 需求拆解 + 调试验收"的能力。

典型的一人全栈工作流：

1. 用自然语言向 AI 描述产品："我要一个记账小程序，语音输入，自动分类"。
2. AI 生成前端页面 + 后端接口 + 数据库表结构。
3. 你负责跑起来、测试、指出 bug 让 AI 修。
4. 部署上线，见 [[部署与上线]]。

## 全栈 vs 专精的取舍

| 维度 | 全栈 | 专精 |
| --- | --- | --- |
| 学习成本 | 面广，每层懂到"够用"即可 | 面窄，一层钻得很深 |
| 独立做产品 | 一个人就能跑通全流程 | 需要组队协作 |
| 技术深度 | 复杂问题（高并发、性能调优）吃力 | 能解决领域内的硬问题 |
| 适合人群 | 独立开发者、创业者、AI 爱好者 | 大厂工程师、领域专家 |

## 常见的个人全栈技术组合

| 组合 | 构成 | 适合 |
| --- | --- | --- |
| Python 流 | FastAPI + SQLite + 简单前端 | AI 应用、个人工具，本库主推 |
| JavaScript 流 | Next.js（前后端一体）+ PostgreSQL | Web 产品、想一语言走天下 |
| 小程序流 | 微信原生小程序 + 云托管 | 微信生态产品，见 [[微信小程序开发入门]] |

> [!tip] 学习建议
> 零基础走 AI 开发路线，推荐"**T 型策略**"：横向了解全栈每层是干什么的（这篇笔记 + [[前端与后端]] + [[数据库入门]]），纵向把 Python 后端这一竖扎深（[[Python学习路线]] → [[面向AI开发的Python]]）。AI 应用的核心逻辑大多在后端，前端可以大量交给 AI 生成。

> [!warning] 常见误区
> - **以为全栈 = 什么都自己写**：全栈是"能跑通"，不是"每层都手写"。AI 工具、现成模板、云服务都是你的杠杆。
> - **一上来追求复杂架构**：个人项目用 FastAPI + SQLite 就够了，见 [[用AI开发App全流程]]。
