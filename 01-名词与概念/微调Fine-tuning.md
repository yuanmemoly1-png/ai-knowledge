# 微调 Fine-tuning

## 什么是微调

微调（Fine-tuning）是在已经预训练好的 [[LLM大语言模型]] 基础上，用你自己的数据**继续训练**，让模型的行为、风格或领域知识向你的需求靠拢。

和 [[Prompt与提示词工程]]、[[RAG检索增强生成]] 不同，微调改变的是**模型本身的参数**——前两者只是"给模型更好的输入"，微调是"把模型本身改掉"。

## 微调 vs RAG vs Prompt：怎么选

| 维度 | Prompt 工程 | RAG | 微调 |
| --- | --- | --- | --- |
| 解决什么 | 任务格式、语气、简单约束 | 注入外部/最新/私有知识 | 固化行为模式、风格、领域能力 |
| 成本 | 几乎为零 | 中（建库+维护） | 高（数据+算力+训练） |
| 见效速度 | 分钟级 | 天级 | 周级 |
| 知识更新 | 每次手动改 | 更新文档即可 | 需要重新训练 |
| 数据要求 | 无 | 文档库 | 数百到数万条高质量训练样本 |
| 适合阶段 | 永远先做 | 知识型任务首选 | 前两者都试过后仍不满足 |

> [!tip] 决策口诀
> **先 Prompt，再 RAG，最后才微调。** 90% 的需求前两步就能解决。微调是"重武器"，用在行为模式和风格上，不要用它灌输事实知识——那会很快过时且容易遗忘，知识交给 RAG。

## 主流微调方式

### 全参微调（Full Fine-tuning）

更新模型的全部参数。效果上限最高，但成本巨大：一个 7B 模型全参微调需要上百 GB 显存，普通个人显卡完全跑不动。

### LoRA（低秩适配）

**Low-Rank Adaptation**：冻结原模型参数不动，只在每层旁边加一对很小的低秩矩阵，只训练这对小矩阵。

- 可训练参数量降到原来的 0.1%-1%，消费级显卡（如 24GB 显存）可微调 7B 级模型。
- 训练产物是几十 MB 的"适配器"文件，可为不同任务保存多个 LoRA 随时切换。
- 效果在多数任务上接近全参微调，是当前事实标准。

### QLoRA

LoRA 的省显存加强版：把原模型权重量化成 4-bit 加载，再叠加 LoRA 训练。显存需求再降一半以上，单张 24GB 显卡可微调 13B-33B 级模型。

```python
# 使用 peft 库给模型包一层 LoRA 的典型代码（示意）
from peft import LoraConfig, get_peft_model

config = LoraConfig(
    r=16,               # 低秩矩阵的秩，常用 8-64
    lora_alpha=32,
    target_modules=["q_proj", "v_proj"],  # 对注意力层加适配器
    lora_dropout=0.05,
)
model = get_peft_model(base_model, config)
model.print_trainable_parameters()  # 通常显示不到 1% 的参数可训练
```

## SFT 与 RLHF

- **SFT（Supervised Fine-Tuning，监督微调）**：用"指令 → 理想回答"成对数据训练，教模型怎么按指令干活。ChatGPT 类模型的第一步训练就是它。个人开发者说的"微调"通常指 SFT。
- **RLHF（Reinforcement Learning from Human Feedback，人类反馈强化学习）**：先训练一个"奖励模型"学习人类偏好（哪个回答更好），再用强化学习让模型向高奖励方向优化。ChatGPT 变得"听话、无害"主要靠它。近年出现了 DPO 等更简单的替代方案。

> [!note] 想动手练
> 用 transformers + peft + trl 三个库就能在单卡上完成一次 QLoRA SFT，数据集格式是 JSONL（每行一条 instruction/output）。深入教程见 [[从零实现LLM专题]] 和 [[Raschka教授资源全集]]。

## 什么时候才值得微调

> [!example] 值得微调的信号
> - 需要模型**稳定输出特定格式**（如医疗病历结构化），few-shot 塞示例已撑爆[[上下文窗口]]。
> - 需要**独特的语气/人格**（客服腔、法律顾问腔），且要服务海量请求——微调后每次调用就不用带长 system prompt，省 token。
> - 专业领域术语密集（法律、医学、芯片），通用模型频繁误解术语含义。
> - 已有几百条以上高质量"输入→理想输出"数据，且任务模式相对固定。

> [!warning] 不值得微调的情况
> 只是想让模型"知道"某些事实（公司制度、产品手册、最新资讯）——这是 RAG 的活，微调灌知识既贵又会随模型更新而失效。
