# 幻觉 Hallucination

## 什么是幻觉

幻觉（Hallucination）指 [[LLM大语言模型]] 生成**看起来合理、实际是编造**的内容：不存在的论文、虚构的法条、张冠李戴的史实、凭空捏造的 API 函数名。

根本原因：模型的本质是"基于概率的下一个 [[Token与分词|Token]] 预测器"，它学的是**语言的统计规律**，不是事实数据库。当训练数据里没有可靠答案时，它不会停下来，而是按"最像正确答案的样子"继续编——自信和胡说不冲突。

典型表现：

- 引用真实作者 + 编造的书名/论文标题
- 给出格式完美但不存在的链接
- 写代码时调用库里根本没有的函数
- 对不确定的问题给出斩钉截铁的错误答案

## 危害

| 场景 | 后果 |
| --- | --- |
| 法律/医疗咨询 | 引用虚构法条或错误剂量，可能直接造成伤害 |
| 编程 | 幻觉 API 浪费调试时间，见 [[VibeCoding方法论]] 中的避坑部分 |
| 客服/企业问答 | 向客户承诺不存在的政策，引发纠纷 |
| 新闻写作 | 编造引语和数据，损害公信力 |

> [!warning] 核心认知
> **默认模型可能胡说，让它证明而不是让它保证。** 所有高风险用途都必须有人工或程序校验环节。

## 缓解方法

### 1. RAG：给模型"参考资料"

让模型基于检索到的真实文档作答，而不是凭记忆。这是最有效的工程手段，详见 [[RAG检索增强生成]]。

### 2. 要求引用来源

在 Prompt 里强制要求标注出处，没有来源就拒绝回答：

```python
system_prompt = """基于给定资料回答问题。
规则：
1. 每个结论后标注来源编号，如 [1]。
2. 资料中没有的信息，回答"根据现有资料无法回答"。
3. 禁止补充资料之外的任何知识。"""
```

### 3. 调低 temperature

`temperature` 控制采样的随机性：

| 取值 | 行为 | 适用 |
| --- | --- | --- |
| 0 ~ 0.3 | 保守，总选最可能的词 | 事实问答、代码、抽取 |
| 0.7 ~ 1.0 | 有创造性 | 写作、头脑风暴 |
| > 1.0 | 高度随机 | 几乎不建议用于生产 |

事实型任务用低 temperature 能明显减少编造（但不能根除）。

```python
resp = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": question}],
    temperature=0,  # 事实类任务直接压到 0
)
```

### 4. 工具验证：让程序兜底

对可程序化验证的输出，用工具检查而不是信模型：

- 模型生成的 URL → 程序发请求检查是否存在
- 模型生成的代码 → 实际运行，报错就回喂给模型修正（见 [[Agent评估与调试]]）
- 模型给出的计算结果 → 让它调用计算器/代码解释器（[[FunctionCalling函数调用]]）

### 5. 自我反思与多轮校验

让模型先回答，再追加一轮"请检查上述回答中哪些陈述无法从资料中得到证实"。成本翻倍但适合高价值场景。

## 一个现实建议

> [!tip] 分层设防
> 学习笔记、草稿写作 → 低 temperature 即可；对外客服、知识库问答 → RAG + 引用来源；法律、医疗、金融 → 前面全部 + 人工复核。幻觉无法 100% 消除，只能按风险等级配置防御深度。
