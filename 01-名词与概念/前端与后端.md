# 前端与后端

## 一句话区分

- **前端（Frontend）**：运行在用户设备上、用户能直接看到和点击的部分。
- **后端（Backend）**：运行在远程服务器上、用户看不见的逻辑和数据处理。

用餐厅比喻：前端是**大堂和菜单**（顾客接触的一切），后端是**厨房**（真正做菜的地方），两者通过**服务员（API）**传话，见 [[API接口]]。

## 前端技术栈

| 技术 | 作用 | 类比 |
| --- | --- | --- |
| HTML | 页面结构（标题、按钮、表格） | 房子的框架 |
| CSS | 样式（颜色、布局、动画） | 装修和家具 |
| JavaScript | 交互逻辑（点击响应、发请求） | 电器和开关 |

实际开发很少裸写这三样，通常用**前端框架**提高效率：

- **React**：Meta 出品，生态最大，AI 编程工具默认生成最多的就是它。
- **Vue**：上手更平缓，中文资料多，国内流行。
- **小程序框架**：微信原生 / uni-app，做微信生态应用用，见 [[微信小程序开发入门]]。

## 后端技术栈

后端可用很多语言写，AI 开发场景最常见两种：

| 方案 | 特点 | 适合 |
| --- | --- | --- |
| Python + FastAPI | 语法简单、AI 生态最好（调 LLM、向量库都方便） | AI 应用首选 |
| Node.js + Express | 和前端同用 JavaScript，一份语言走天下 | 前端出身转全栈 |

一个最小的 FastAPI 后端：

```python
from fastapi import FastAPI

app = FastAPI()

@app.get("/hello")          # 声明一个 GET 接口，路径 /hello
def hello(name: str = "朋友"):
    return {"msg": f"你好，{name}"}   # 返回 JSON 数据

# 启动：pip install fastapi uvicorn，然后运行 uvicorn 文件名:app
# 浏览器访问 http://127.0.0.1:8000/hello?name=小明 即可看到返回
```

## 前后端如何通信：一次完整的请求-响应

```
浏览器/小程序 (前端)                      服务器 (后端)
      │                                    │
      │  ① HTTP 请求                        │
      │  GET /hello?name=小明   ───────────▶│ ② 路由匹配到 hello 函数
      │                                    │ ③ 执行逻辑（可能查数据库、调 LLM）
      │  ④ HTTP 响应                        │
      │  {"msg": "你好，小明"}   ◀───────────│
      │                                    │
      ▼  ⑤ 拿到 JSON，渲染到页面上
```

关键点：

1. 前后端之间只传**数据**（通常是 JSON 格式），不传页面代码。
2. 前端通过 **API** 调用后端，一个后端可以同时服务网页、小程序、App 多个前端。
3. 涉及 [[LLM大语言模型]] 的应用，通常是**后端**去调模型 API（保护 API Key 不暴露在前端），再把结果转给前端。

> [!example] 一个 AI 应用的数据流
> 用户在前端输入问题 → 前端把问题 POST 到后端 `/chat` 接口 → 后端调用 LLM API（如 OpenAI）→ 拿到回答 → 返回给前端 → 前端渲染对话气泡。你的后端相当于 LLM 和用户之间的"中转站"。

> [!tip] 零基础怎么选
> 走 AI 开发路线：后端学 **Python + FastAPI**（顺接 [[面向AI开发的Python]]），前端不必深学——让 AI 工具生成 React/Vue 页面，你看得懂结构、会提修改要求即可，这正是 [[VibeCoding方法论]] 的核心。
