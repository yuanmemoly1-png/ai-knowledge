# 多模态

## 什么是多模态

模态（Modality）指信息的载体类型：文本、图像、音频、视频等。**多模态（Multimodal）模型**就是能同时处理多种模态输入/输出的模型——你给它一张图配一段文字提问，它看图回答；或者你说一段话，它生成一张图。

早期的 AI 是"专科医生"：翻译模型只翻译，图像分类模型只认图。多模态模型则是"全科医生"，在同一个模型里打通了不同感官。

## 各模态的典型模型与能力

| 模态 | 代表模型 | 能做什么 |
| --- | --- | --- |
| 文本 | GPT、Claude、DeepSeek、Qwen | 对话、写作、代码（见 [[LLM大语言模型]]） |
| 图像理解 | GPT-4o、Claude、Gemini、Qwen-VL | 看图问答、读图表、识别截图 |
| 图像生成 | DALL·E、Midjourney、Stable Diffusion、即梦 | 文生图、图片编辑 |
| 音频 | Whisper（语音识别）、TTS 系列、Suno（音乐） | 语音转文字、文字转语音、作曲 |
| 视频理解 | Gemini、GPT-4o | 理解视频内容、总结监控画面 |
| 视频生成 | Sora、可灵、即梦 | 文生视频、图生视频 |

## VLM 视觉语言模型

开发者最常打交道的是 **VLM（Vision-Language Model，视觉语言模型）**：在 LLM 基础上接入视觉编码器，让模型"看懂"图片。实现思路简化为：

1. 图像编码器（如 ViT）把图片切成小 patches，编码成一串视觉向量。
2. 通过投影层把视觉向量映射到与文本 [[Embedding向量嵌入]] 相同的空间。
3. 视觉向量与文本 token 拼接，一起送进 LLM，统一做"下一个 token 预测"。

调用 API 时，图片就是消息里的一种内容类型：

```python
import base64
from openai import OpenAI

client = OpenAI()

with open("chart.png", "rb") as f:
    img_b64 = base64.b64encode(f.read()).decode()

resp = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{
        "role": "user",
        "content": [
            {"type": "text", "text": "这张图表展示了什么趋势？用三句话总结。"},
            {"type": "image_url",
             "image_url": {"url": f"data:image/png;base64,{img_b64}"}},
        ],
    }],
)
print(resp.choices[0].message.content)
```

## 典型应用场景

> [!example] 已经在落地的场景
> - **截图转代码**：把 UI 设计稿截图发给模型，直接生成前端代码（见 [[VibeCoding方法论]]）。
> - **文档理解**：扫描件、PDF 中的表格和图表直接问答，不用先 OCR。
> - **会议纪要**：录音 → Whisper 转文字 → LLM 总结，全自动流水线。
> - **无障碍**：为视障用户实时描述摄像头画面。
> - **内容审核**：同时理解图文，识别文字审核漏掉的违规图片。
> - **电商**：拍照搜同款、上传户型图出装修方案。

## 学习建议

- 入门从"图像理解"开始：会调 API 发图片就够了，是成本最低的多模态体验。
- 注意多模态的 token 成本：一张图片会被编码成数百到上千 token，影响费用和[[上下文窗口]]，大图建议先压缩。
- 图像生成、视频生成偏"产品使用"，图像/音频理解偏"开发集成"，先想清楚自己要哪条路。
