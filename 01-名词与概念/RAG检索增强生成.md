# RAG 检索增强生成

## 为什么需要 RAG

[[LLM大语言模型]] 有三个绕不开的短板：

1. **知识截止**：训练数据之后的时事、新发布的 API，它不知道。
2. **不懂私有知识**：你公司的内部文档、个人笔记，从未出现在训练语料里。
3. **容易编造**：不知道答案时也可能硬答，即[[幻觉Hallucination]]。

RAG（Retrieval-Augmented Generation，检索增强生成）的思路：**不让模型背知识，而是答题前先去"查资料"**——先从你的知识库里检索出相关内容，连同问题一起发给模型，让它基于资料作答。相当于把闭卷考试变成开卷考试。

## 完整流程

```
                离线建库（只做一次/增量更新）
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ 原始文档  │ → │ 切分chunk │ → │ 嵌入向量  │ → │ 存入向量库 │
└──────────┘   └──────────┘   └──────────┘   └──────────┘

                在线问答（每次提问执行）
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ 用户问题  │ → │ 问题向量化│ → │ 检索Top-K │ → │ 拼接Prompt│ → LLM 生成答案
└──────────┘   └──────────┘   └──────────┘   └──────────┘
```

五个环节逐一说明：

1. **切分（Chunking）**：把长文档切成几百 token 的小块。块太大浪费[[上下文窗口]]，太小丢上下文，通常按段落/标题切并保留少量重叠。
2. **嵌入（Embedding）**：用 Embedding 模型把每个块编码成向量，见 [[Embedding向量嵌入]]。
3. **入库**：向量 + 原文 + 元数据存入向量数据库。
4. **检索**：问题向量化后做相似度搜索，取 Top-K（常见 3-5 个）最相关的块。
5. **生成**：把检索结果塞进 Prompt（"基于以下资料回答：…"），模型生成带来源依据的答案。

## 向量数据库对比

| 数据库 | 定位 | 优点 | 适合场景 |
| --- | --- | --- | --- |
| Chroma | 嵌入式轻量库 | pip 安装即用，零运维 | 学习、原型、小项目 |
| FAISS | Meta 开源的向量检索库 | 极快，纯本地内存计算 | 对性能敏感的自建检索 |
| Milvus | 分布式向量数据库 | 支持海量数据、生产级 | 企业级大规模部署 |

> [!tip] 学习路径
> 入门用 Chroma 最合适；它不够用（数据上百万、要多机部署）时再迁 Milvus。FAISS 是库不是完整数据库（不管存储和元数据），常作为底层引擎。

## 最小可运行示例（Chroma）

```bash
pip install chromadb sentence-transformers
```

```python
import chromadb

client = chromadb.Client()  # 内存模式；持久化用 PersistentClient(path="./db")
# Chroma 默认自带嵌入模型，也可换成 sentence-transformers 的中文模型
collection = client.create_collection("docs")

docs = [
    "公司年假制度：入职满一年可享 5 天带薪年假。",
    "报销流程：在 OA 系统提交发票，3 个工作日内审批。",
    "会议室预约：通过钉钉应用中心预约，最多提前一周。",
]
collection.add(
    documents=docs,
    ids=[f"doc{i}" for i in range(len(docs))],
)

question = "入职多久可以休年假？"
result = collection.query(query_texts=[question], n_results=1)
retrieved = result["documents"][0][0]
print("检索到：", retrieved)

# 把检索结果拼进 Prompt 发给 LLM（此处示意）
prompt = f"基于以下资料回答问题，资料中没有就说不知道。\n资料：{retrieved}\n问题：{question}"
```

## 常见坑

> [!warning] 新手高频翻车点
> - **切分太随意**：按固定字符数硬切，把一句话拦腰切断，检索质量暴跌。要按语义边界（段落、标题）切。
> - **Embedding 模型不匹配语言**：用英文模型处理中文知识库，相似度计算失真。
> - **检索到但没用好**：Top-K 塞太多块，噪音淹没关键信息；通常 3-5 块足够。
> - **以为 RAG 万能**：表格、跨文档推理、需要精确计算的问题，单纯向量检索效果差，需配合关键词检索（混合检索）或[[Agent智能体]]。
> - **没有兜底**：务必在 Prompt 里加"资料中没有就说不知道"，否则模型照样编。
